# 업적과 꾸미기 보상

최종 갱신: 2026-10-17. 현재 브랜치의 기능 범위는 [README](../README.md)를 따른다.

## 현재 동작

`/achievements`는 DB 카탈로그의 공개 업적과 이미 해금한 보관 업적을 표시한다. 총 달성 개수와 다음 목표, 전체·도전 중·달성 완료 필터를 제공하며 미해금 업적을 진행률이 높은 순서로 먼저 보여준다. 이름·목표·보상·공개 여부는 관리자가 편집할 수 있으므로 전체 개수를 코드 상수로 정하지 않는다. `/loadout`에서 소유한 보상을 장착하며 자동 장착하지 않는다. 코인 상품은 실제 구매할 수 있다. [콘텐츠 카탈로그](content-catalog.md) · [상점 거래](cosmetic-shop.md)

과거의 코인 업적 초안은 현재 보상 지급 규칙이 아니다. 코인을 주는 [일일 퀘스트](daily-quests.md)는 대시보드에서 별도로 확인한다.

## 기본 업적

| ID | 조건 | 영구 보상 |
| --- | --- | --- |
| `checkin-7` | 한국 시간 기준 7일 연속 출석 | 희귀 보드 `dawn-oath` |
| `checkin-30` | 한국 시간 기준 30일 연속 출석 | 프로필 `attendance-king` |
| `wins-10` | 유효한 대전 누적 10승 | 프로필 `victory-vanguard` |
| `tile-2048-reward` | 유효한 대전에서 1024 타일 달성 | 에픽 보드 `rune-sanctum` |
| `rank-bronze`–`rank-master` | 최초 평가 완료 후 실제 랭크 최고 기록으로 해당 티어 도달 | 해당 티어 보드·프로필 세트와 하위 단계 보상 |
| `solo-first`, `solo-10min`, `solo-6min`, `solo-4min`, `solo-2min` | 4×4 타임어택 완주·시간 목표 달성 | 단계별 보드 5종 |
| `endless-2048`, `endless-4096`, `endless-8192` | 무한모드의 해당 타일 달성 | 단계별 보드 3종 |
| `achievement-king` | 다른 일반 업적 5개 달성 | 프로필 `achievement-king` |

위 표는 초기 공개 규칙이다. 현재 목록과 관리자 변경은 `content_catalog()`가 반환한 정의를 따른다. `tile-2048-reward`는 기존 해금 기록 보존을 위해 ID를 유지했으며 목표는 1024다. 랭크 영구 수집품은 시즌 종료 순위 보상과 다르다. [랭크 보상 조건](rank-cosmetics.md) · [싱글 보상 조건](solo-time-attack.md)

업적 개수는 한 번이라도 공개된 카탈로그 업적의 해금 중 `metric`이 `achievements`가 아닌 항목을 센다. 이미 보관된 업적도 포함하지만 업적왕 등 컬렉션 업적은 모두 제외한다. 컬렉션 보상이 다른 컬렉션 보상을 연쇄 해금하지 않는다.

## 출석·경기 집계

- 로그인 계정은 페이지 방문 시 자동 출석한다. 서버의 `Asia/Seoul` 날짜를 사용하며 클라이언트 날짜를 받지 않는다. 조회·출석 오류는 재시도할 수 있다.
- 같은 날 요청은 한 번만 반영한다. 다음 날 출석은 연속 일수를 늘리고 하루 이상 빠진 뒤 출석하면 1일부터 시작한다. 최고 연속 기록과 이미 얻은 보상은 유지한다. 새 카탈로그 출석 업적은 최고 연속 기록으로도 평가한다.
- 경기 업적은 서로 다른 비익명 계정 두 명의 서버 저장 일반전·랭크전만 집계한다. 친구전·게스트·동일 계정 대전은 제외한다. 서버가 확정한 기권 결과도 포함한다.
- 승수 진행도는 전체 유효 누적 승수를 반환하고 각 카드가 목표에 맞게 표시한다. 시즌 전환은 누적 실적이나 영구 보상을 초기화하지 않는다.
- 경기 기록과 보상은 DB 트랜잭션으로 처리한다. 경기 ID와 `(player_id, achievement_id)` 고유 제약으로 재전송·동시 요청의 중복 해금을 막는다.
- 과거 경기의 참가 자격을 확인할 수 있을 때만 소급한다. 상대 계정이 이미 삭제된 과거 일반전은 제외될 수 있다. 새 경기의 `matches.achievement_eligible`은 이후 상대 탈퇴에도 자격을 보존한다.

## 정의·데이터·권한

| 구현 | 역할 |
| --- | --- |
| `private.achievement_catalog`, `content_catalog()` | 실제 업적 정의와 클라이언트 공개 목록 |
| `player_attendance` | 마지막 출석일·현재/최고 연속 일수 |
| `achievement_unlocks` | 계정별 영구 해금 시각 |
| `sync_achievements()` | 본인 서버 기록으로 새 규칙을 평가한 뒤 상태 반환 |
| `achievement_state()` | 상태 읽기 전용 조회 |
| `check_in()` | 서버 날짜로 출석하고 업적 평가 |
| `record_match()` | 서버 전용 경기 저장·집계 |
| `record_solo()`, `record_solo_endless()` | 서버 전용 싱글 기록·업적 집계 |
| `player_preferences`의 권한 검사 | 보유하지 않은 보드·프로필 장착 거절 |

웹의 업적 훅은 `sync_achievements()`를 사용하므로 재방문한 이용자도 새로 공개된 규칙을 평가받는다. 클라이언트는 달성 점수나 해금을 직접 제출하지 않는다. 소켓도 서버에서 확인한 장착 정보만 적용한다. 조회 실패를 미해금으로 확정하지 않고 재시도를 제공한다.

관리자는 공개한 업적을 보관할 수 있지만 기존 해금은 취소하지 않는다. 목표를 높여도 받은 보상은 유지된다. 지급형 꾸미기와 코인 구매형 꾸미기는 별도 획득 경로다. 기본 무료 범위·가격 확인·동시 구매·이전 장착 정리는 [상점 문서](cosmetic-shop.md)에 정리한다.

## 배포와 검증

대상 DB의 실제 이력과 통합 후속 마이그레이션을 확인한다. 카탈로그가 이미 적용된 DB에 이전 업적·솔로 파일을 다시 실행하지 않는다. 이미 적용한 파일은 수정하지 않는다. [배포 절차](deployment.md) · [환경별 통합 이력](full-performance/integration.md)

검증 경로는 `apps/socket/tests/achievement-unlocks.test.ts`, `rank-cosmetics.test.ts`, `catalog.test.ts` 및 웹의 `achievement-unlocks.browser.mjs`, `dynamic-catalog.browser.mjs`다. 실제 파일명과 실행 명령은 각 기능의 테스트 목록을 확인한다. 초기 보상 4종 제작·권한·동시성 결과는 [당시 검증 기록](achievement-rewards/verification.md)에 보존한다.

경기당 완료 10코인·승리 5코인, 반복 상대 제한 등의 과거 경제안은 적용된 지급 규칙이 아니다. 현재 코인은 대시보드의 일일 퀘스트 완료 시 한국 시간 하루 최대 120코인까지 지급한다.
