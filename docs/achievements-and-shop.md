# 업적 해금 · 코인 상점 설계

최종 갱신: 2026-10-17

## 현재 구현

**꾸미기 보상을 영구 해금하는 업적 4종**은 출석·경기 기록부터 실제 장착까지 연결한다. `/achievements`에서 출석과 진행도를 확인하고, `/loadout`에서 보상을 미리 보거나 장착한다. 기존 스킨 20종·프로필 6종은 로그인 계정에 계속 무료로 제공하며, 새 보드 2종·프로필 2종만 업적으로 해금한다.

코인 보상 중심의 기존 업적 6종과 상점 19종은 여전히 **카탈로그·화면 골격**이다. 코인 지급·차감·구매는 실행하지 않는다. `/achievements`의 `준비 중인 추가 업적`은 기본적으로 접혀 있으며, 미집계 진행도를 0이나 완료로 표시하지 않는다. 상점에는 예정 가격을 명시한다.

## 실제 해금 업적

정의는 [보상 카탈로그](../packages/schema/achievements.ts), 판정·소유권은 [업적 마이그레이션](../supabase/migrations/20261017030000_achievement_unlocks.sql)이 기준이다.

| ID | 업적 | 조건 | 영구 해금 보상 |
| --- | --- | --- | --- |
| checkin-7 | 일곱 번의 새벽 | 한국 시간 기준 7일 연속 출석 | 희귀 보드 `dawn-oath` · 새벽의 서약 |
| checkin-30 | 출근왕 | 한국 시간 기준 30일 연속 출석 | 프로필 `attendance-king` · 출근왕 |
| wins-10 | 승리의 선봉 | 유효한 대전 누적 10승 | 프로필 `victory-vanguard` · 승리의 선봉 |
| tile-2048-reward | 룬의 각성 | 유효한 대전에서 2048 타일 달성 | 에픽 보드 `rune-sanctum` · 룬의 성소 |

### 출석과 경기 집계

- 로그인 후 **오늘 출석하기**를 눌러 기록한다. 페이지 방문만으로 출석하지 않는다. 날짜는 서버의 `Asia/Seoul` 자정 기준이며 클라이언트 날짜는 받지 않는다.
- 같은 날 여러 번 요청해도 한 번만 반영한다. 다음 날 출석하면 연속 일수가 증가하고, 하루 이상 빠지면 다음 출석에서 1일부터 시작한다. 최고 연속 기록과 이미 해금한 보상은 유지한다.
- 경기 업적은 서버에 저장된 일반전·랭크전 중 서로 다른 비익명 계정 두 명이 참가한 결과만 집계한다. 친구전·게스트·동일 계정 대전은 제외한다. 기권 등 서버가 확정한 결과도 포함하며, 아래 미확정 코인 지급의 최소 시간·이동 수 조건은 적용하지 않는다.
- 경기 저장과 보상 해금은 같은 트랜잭션이다. 경기 ID와 계정별 업적 ID의 고유 제약으로 재전송·동시 요청의 중복 해금을 막는다. 별도 보상 수령 버튼은 없으며 장착은 사용자가 선택한다.
- 시즌이 바뀌어도 누적 실적과 해금은 유지한다. 10승 진행도 조회는 목표값 10에서 멈추며 전체 전적의 승수를 대체하지 않는다.
- 마이그레이션은 판정할 수 있는 과거 경기에도 보상을 소급한다. 과거 일반전에서 상대 계정이 이미 삭제돼 참가 자격을 확인할 수 없는 경우는 제외한다. 새 경기는 `matches.achievement_eligible`에 자격을 기록하므로 이후 상대가 삭제돼도 내 진행도가 사라지지 않는다.

### 데이터와 권한

| 구현 | 역할 |
| --- | --- |
| `player_attendance` | 계정별 마지막 출석일·현재 연속 일수·최고 연속 일수 |
| `achievement_unlocks` | `(player_id, achievement_id)`별 영구 해금 시각 |
| `achievement_state()` | 본인 출석 상태·경기 진행도·해금 목록 조회 |
| `check_in()` | 서버 날짜로 출석 처리 후 최신 상태 반환 |
| `player_preferences` 트리거 | 해금하지 않은 전용 스킨·프로필 저장 거절 |

인증 계정은 본인 데이터만 읽고 테이블에 직접 쓰지 못한다. 출석 쓰기는 인증된 `check_in()`만, 경기 저장은 서버 전용 `record_match()`만 수행한다. 소켓 서버도 DB에서 읽은 장착 스킨과 비교해 전용 보드 요청을 검증한다. 해금 정보 조회 실패를 미해금이나 성공으로 단정하지 않고 재시도를 제공한다.

`20261017030000_achievement_unlocks.sql`은 앞선 마이그레이션 다음, 앱 배포 전에 적용해야 한다. **원격 DB 적용과 운영 배포는 아직 하지 않았다.**

## 준비 중인 추가 업적

아래 6종은 [기존 경제 카탈로그](../packages/schema/economy.ts)의 초기 기획값이다. 아직 진행도 집계·보상 지급을 실행하지 않는다.

| ID | 이름 | 조건 | 예정 보상 |
| --- | --- | --- | --- |
| first-finish | 첫 발걸음 | 유효한 대전 1회 완료 | 50코인 |
| first-win | 첫 승리 | 유효한 대전 1회 승리 | 75코인 |
| ten-finishes | 꾸준한 도전자 | 유효한 대전 10회 완료 | 150코인 |
| tile-1024 | 한 걸음 앞으로 | 실전에서 1024 타일 생성 | 100코인 |
| tile-2048 | 2048의 주인 | 실전에서 2048 타일 생성 | 용 프로필 아이콘 |
| ranked-placement | 첫 배치 완료 | 생애 첫 랭크 10경기 평가 완료 | 100코인 |

용 프로필은 기존 무료 이용 권한을 유지한다. 준비 중인 `tile-2048`과 실제 룬의 성소를 해금하는 `tile-2048-reward`는 별도 정의다. 기존 무료 아이템을 유료·업적 전용으로 전환하려면 기존 이용자의 보유권을 보존하는 별도 마이그레이션이 필요하다.

향후 진행도 상태는 `집계 전 → 진행 중 → 달성/지급 완료`다. 경기 저장 트랜잭션에서 진행도와 보상을 함께 기록하며 별도의 수령 버튼은 두지 않는다. 오류는 미집계 상태와 구별하고 재시도로 중복 지급되지 않아야 한다.

## 코인 상점

판매 대상은 꾸미기뿐이다. 능력, 점수, 승률에 영향을 주는 상품은 판매하지 않는다. 첫 버전은 고정 상품만 사용하고 랜덤 상자·기간 한정 할인·실물 결제는 제외한다.

| 등급 | 예정 가격 | 기준 |
| --- | ---: | --- |
| 일반 | 150 | 보드 색·재질 |
| 희귀 | 300 | 타일 패턴 |
| 에픽 | 600 | 배경과 타일 테마 |
| 레전더리 | 1,200 | 캐릭터·상징 타일, 전용 합성 모션·소리 |

클래식은 항상 기본 제공한다. 나머지 기존 스킨 19종으로 상점 미리보기를 구성하지만 실제 판매는 하지 않는다. 새벽의 서약·룬의 성소는 업적 전용이므로 상점 목록에서 제외한다. 가격은 스킨의 현재 무료 이용 가격과 구별해 상품 카탈로그의 `plannedPrice`에만 둔다. 상세 미리보기는 장착 설정을 바꾸지 않으며 레전더리는 사용자가 눌러야 모션·소리가 재생된다.

## 보상 경제 — 출시 전 조정할 초안

- 유효한 일반전·랭크전 완료 10코인, 승리 보너스 5코인. 무승부는 완료 보상만 지급한다.
- 유효 경기 초안: 양측 유효 이동 10회 이상, 경기 시간 60초 이상. 탈주 종료·기권 종료는 지급하지 않는다.
- 반복 상대는 UTC 하루에 같은 상대에게 최대 3경기까지만 보상, 경기 보상은 하루 최대 150코인. 업적 보상은 이 한도와 분리한다.
- 수치는 실제 경기 시간과 이동 수 분포를 확인한 후 확정한다. 짧지만 정상적인 경기의 배제율도 확인한다.
- 배치 완료 업적은 랭크의 공식 배치 완료 기록을 사용한다. 시즌이 바뀌어도 같은 업적을 반복 수령할 수 없다.

## 거래 계층의 최소 계약 — 다음 구현 단계

아래는 코인 지급·구매를 활성화할 때의 설계이며 아직 만들지 않았다. 현재의 전용 꾸미기 보유권은 `achievement_unlocks`로 판정하고, 별도 범용 인벤토리·코인 원장은 추가하지 않는다.

| 데이터 | 고유 키와 역할 |
| --- | --- |
| 코인 업적 진행도 | `(player_id, achievement_id)` · 진행량, 달성 시각, 정의 버전 |
| 아이템 보유권 | `(player_id, item_kind, item_id)` · 최초 획득 경로·시각 |
| 코인 원장 | `(player_id, source, source_id)` · 증감액, 변경 후 잔액, 서버 시각 |
| 지급 처리 기록 | `(match_id, player_id)` · 보상 0인 경기까지 처리 이유를 기록 |

구매 요청은 상품 ID와 재시도용 요청 ID만 받는다. 가격·잔액·보유 여부는 서버가 조회한다. 지갑 행을 잠그고 `중복 요청 확인 → 상품/권한/가격 검증 → 잔액 확인 → 차감+보유권+원장`을 하나의 DB 트랜잭션으로 실행한다. 보유 상품은 재차감하지 않고, 실패는 전체 롤백한다. 인증 계정은 자신의 진행도·지갑·원장만 읽고 클라이언트 직접 쓰기는 허용하지 않는다.

출시 전 필수 검증: 동시 구매, 잔액 부족, 위조 가격, 음수·큰 수, 동일 요청 재전송, 서로 다른 요청으로 같은 상품 구매, 지급 도중 재시작, 시즌 전환 직전/직후 결과, 삭제된 계정, 중복 경기, 서버 저장 실패. 활성화 시 기존 무료 스킨 보유권 이관과 원장/잔액 대조 도구도 함께 제공한다.
