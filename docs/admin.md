# 관리자 화면과 밸런스 통계

관리자는 모노레포의 별도 Next.js 앱 `apps/admin`이다. 로컬 주소는 `http://localhost:3100`이며 게임 `apps/web`의 `/admin` 경로는 제거했다. 같은 Supabase 계정을 사용하지만 관리자 앱에서 따로 로그인하고, `sb-2048-admin-auth` 쿠키로 게임 로그인과 세션을 분리한다. DB의 `admin_roles`에 등록된 계정만 접근할 수 있으며 이메일이나 사용자 수정 가능 metadata로 관리자 권한을 판단하지 않는다.

새 체크아웃에서는 `apps/admin/.env.example`을 `.env.local`로 복사해 공개 Supabase URL과 공개 키만 설정한다. `pnpm dev:admin`으로 독립 실행하거나 루트 `pnpm dev`로 게임 웹·소켓과 함께 실행한다. 서비스 키는 관리자 앱에 넣지 않는다. 게임 웹의 관리자 링크는 `NEXT_PUBLIC_ADMIN_URL`을 사용한다. 배포할 때도 `apps/web`과 `apps/admin`을 서로 다른 프로젝트와 도메인으로 연결한다.

현재 관리자 로그인은 이메일·비밀번호 방식이며 Google 전용 계정 로그인은 제공하지 않는다. 게임과 관리자는 각자 현재 세션만 로그아웃한다. 로컬의 포트 차이는 쿠키 보안 경계가 아니므로 운영에서는 별도 호스트와 HTTPS를 사용한다.

## 화면

- **Overview:** 최근 7·30·90일과 전체·일반전·랭크전·친구전 필터, 경기 수, 참가 계정 수, 평균 경기 시간·점수·이동 수, 일별 경기 수, 종료 사유, 모드 분포, 현재 티어 분포, 공격 종류별 통계.
- **Players:** 이름·이메일·계정 ID 검색, 50개 단위 목록, 레이팅·가입일·이용 상태.
- **Player detail:** 최근 20경기, 경기별 공격 통계와 Elo 변화, 관리 작업 이력, 사유를 남기는 이용 정지·해제.

일별 집계는 Asia/Seoul 날짜 기준이다. 티어 분포는 현재 레이팅의 전체 스냅샷이며 조회 기간의 과거 티어가 아니다. 참가 계정 수는 선택한 경기의 중복 제거 계정 수로, 계정 ID가 없는 게스트는 포함하지 않는다.

## 수집 기준

서버가 경기를 종료할 때 참가자별 집계만 저장한다. 원시 키 입력·IP 주소·기기 추적 정보는 추가 수집하지 않는다.

| 값 | 의미 |
|---|---|
| moves | 보드가 실제 바뀐 이동 수. 무효 입력 제외 |
| charged | 256·512 병합으로 실제 보유량이 증가한 공격권. 보유 한도 초과분 제외 |
| sent | 서버가 수락해 공격권을 차감한 발사 수. 거절·중복 입력 제외 |
| received | 해당 보드에 실제 배치된 장애물 수. 도착 예정인 공격 제외 |

충전·발사·수신은 X와 하드 블록을 나눠 기록한다. 종료 시 아직 도착하지 않은 공격 때문에 발사와 수신 수량이 다를 수 있다. 게스트끼리의 완료 경기 역시 익명 참가 결과로 집계한다. 게스트에게 개인 경기 기록이나 Elo를 부여하지 않는다.

수집 전 기록과 이전 outbox에는 telemetry가 없다. 화면에서 미수집 표본으로 표시하고 공격·이동 평균의 분모에서 제외한다. `0`은 수집된 경기에서 실제로 해당 행동이 없었다는 뜻이다.

‘공격을 사용한 참가자의 승률’은 참가 경기 표본의 상관관계다. 실력이 높은 사람이 더 많은 공격권을 만드는 효과 등이 섞이므로 공격이 승리의 원인이라는 뜻은 아니다. 표본 수·경기 모드·종료 사유와 함께 확인한다. 경기 시간에는 연결 대기와 일시정지 시간이 포함된다.

## 유저 관리

이용 정지·해제는 사유와 최종 확인이 필요하다. DB가 관리자 권한을 매번 확인하고 계정 상태 변경과 감사기록을 한 트랜잭션으로 저장한다. 본인이나 다른 관리자 계정의 정지는 허용하지 않는다. 계정 삭제·Elo 수동 변경·관리자 권한 편집 UI는 제공하지 않는다.

정지는 새로운 일반전·랭크전·친구전 참가에 적용한다. 대기 중이거나 친구 방을 만든 계정도 실제 매치 생성 전에 다시 확인한다. 진행 중인 경기, 항복과 재접속은 계속 허용한다. 조회 실패 시 로그인 계정의 새 경기 시작을 보류한다. 로그아웃 후 게스트로 플레이하는 것을 계정 정지만으로 차단하지 않는다.

## 관리자 최초 지정

회원가입과 이메일 인증을 완료한 비익명 계정의 UUID를 확인한 후, 신뢰된 DB 관리 경로에서 `admin_roles.user_id`에 등록한다. 서비스 키를 웹 환경이나 브라우저에 넣지 않는다. 계정이 없으면 관리자 권한 부여를 먼저 진행하지 않는다.

테스트에서 만든 관리자·일반 계정과 관리 이력은 검증 후 해당 테스트 데이터만 삭제한다. 실제 사용자의 정지 상태를 테스트 목적으로 변경하지 않는다.

## 운영 한계

경기 중 서버 프로세스가 종료되면 미완료 경기는 집계하지 못한다. 완료 결과는 기존 디스크 outbox와 중복 저장 방지 RPC를 사용하므로 영구 볼륨이 필요하다. 게임 서버는 현재 한 인스턴스를 전제로 한다. 관리자 화면은 완료 경기 집계이며 실시간 동접 모니터가 아니다.

접근 제어는 [Supabase DB 함수 권한](https://supabase.com/docs/guides/database/functions)과 [Next.js 서버 권한 검사](https://nextjs.org/docs/app/guides/authentication)에 따라 화면과 데이터 호출에서 각각 확인한다.

## 확장 계획

현재 구현의 부족한 점과 추가 기능의 우선순위·화면·데이터·완료 기준은 [어드민 확장 기획서](admin-expansion-plan.md)에 정리했다. 이 문서는 구현 제안이며 현재 제공 기능과 구분한다.
