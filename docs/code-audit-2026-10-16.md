# 코드·백엔드 점검 기록 — 2026-10-16

기존 작업이 모두 끝난 뒤 당시의 변경 파일과 미추적 파일을 백업하고 점검했다. 기존 멀티플레이, 인증, 관리자, 설정, 능력, 프로필·스킨, DB 마이그레이션 및 UI 작업을 보존했다. 아래 내용은 그 위에 추가한 수정과 검증 결과다. 운영 배포는 실행하지 않았다.

## 수정한 문제

| 문제 | 조치 | 검증 |
|---|---|---|
| 결과 outbox의 최초 디스크 쓰기가 실패하면 재시도할 JSON 파일 자체가 없어 결과가 재시도 대상에서 빠짐 | 디스크에 쓰기 전까지 메모리에서도 보관하고 재시도. 파일 flush 후 rename, 원격 저장 순서 및 계정별 랭크 대기 유지 | 디렉터리를 파일로 막아 저장 실패를 재현한 후 복구·재전송 테스트 |
| Fly 프록시 뒤에서 피드백·계정 삭제 요청 제한이 실제 사용자별로 분리되지 않음 | Fly 환경에서 유효한 `Fly-Client-IP`만 사용. 직접 실행에서는 TCP 상대 주소 사용 | IPv4·IPv6 사용자 분리, 위조 헤더 무시, 잘못된 헤더 fallback 테스트 |
| 게임 중 설정 저장 오류·재시도가 Socket.IO 연결 effect를 다시 실행함 | 최초 설정 준비 여부로 연결 의존성을 고정 | 저장 실패와 재시도 후에도 연결이 한 번만 생성되는 브라우저 회귀 테스트 |
| `/test`의 난수 보드·localStorage 초기화가 SSR과 불일치하고 저장소 접근 실패가 게임을 중단할 수 있음 | SSR 초기값 고정, 브라우저에서 초기화, 잘못된 저장값 무시, 저장 실패를 표시하면서 메모리 점수 유지 | 저장값 존재·손상·접근 차단 조건에서 hydration·게임 동작 확인 |
| `/test`의 전역 터치/키 입력이 화면 스크롤·브라우저 단축키·메뉴 입력을 가로챔 | 기존 BoardView 스와이프 재사용. 입력 필드·메뉴·이미 처리된 이벤트와 Ctrl/Meta/Alt 조합 제외 | 보드 스와이프, 보드 밖 스크롤, 단축키와 메뉴 키보드 회귀 테스트 |
| 프로필과 지갑을 순차 조회하며 지갑 실패를 실제 잔액 0처럼 표시 | 필요한 프로필 필드만 읽고 두 조회를 병렬 실행. 실패한 잔액은 미확인 상태로 표시 | 타입·린트·전체 브라우저 검사 |
| Docker의 부동 Node 버전/Corepack 의존과 중복 설치, Fly의 임시 결과 저장 경로 | Node 24·pnpm 11.1.3, 소켓 운영 의존성만 설치, Node 직접 실행. 영구 볼륨·30초 종료·자동 정지 해제·HTTP 상태 검사 구성 | 이미지 빌드, 컨테이너 `/health`, 컨테이너 종료 확인 |

새 기능이나 새로운 추상화 계층을 추가하지 않았다. 프로필 조회의 순차 대기와 불필요한 재접속을 없앴지만, 운영 지연 시간이나 처리량 개선 수치를 측정했다고 주장하지 않는다.

## 중복·미사용 코드 정리

TypeScript import/export 그래프와 전체 참조 검색으로 사용 여부를 확인하고 제거했다.

- 미사용 `avatar`, `start-game-modal`, `use-previous`, 전역 `use-swipe`, 빈 `game-core/rules.tsx`, 미사용 achievement 스키마.
- 사용하지 않는 dropdown/input 래퍼와 공개 export, 오래된 DB 스키마·별칭. 실제 `PlayerSchema`와 사용 중인 UI 원시 컴포넌트는 유지.
- 웹의 `@radix-ui/react-avatar`, `uuidv4`, 소켓의 `uuid`, 루트의 미사용 `zod` 의존성.
- 루트 lockfile과 충돌할 수 있는 오래된 `apps/socket/pnpm-lock.yaml`. 루트 워크스페이스 lockfile만 유지.
- `.gitignore`에 Supabase 임시 파일, Docker 컨텍스트 제외 목록에 Git·문서·Supabase 임시 파일 추가.

공개 라우트는 삭제하지 않았으며 기존 `/test` 연습 페이지도 유지했다. 게임 코어·공유 스키마의 호출부와 export 참조를 재확인했다.

## 백엔드·DB 설계 검토

- 게임 보드·이동·능력·승패 판정은 소켓 서버가 소유하고 클라이언트 입력은 스키마로 검증한다. 매칭·방 참가·재접속·중복 연결·퇴장·타임아웃과 경기 종료 경로를 검사했다.
- 계정은 서버가 검증한 Supabase 토큰으로 확정한다. 공개 사용자 ID만으로 경기 연결을 인계하지 않으며, 랭크 경기는 계정 조건과 저장 대기를 확인한다.
- 결과는 디스크 outbox 이후 서버 전용 RPC로 전송한다. 경기 UUID 중복 방지, Elo 순서, 재시도·재시작 시 대기 계정 복구, 잘못된 outbox 거부를 확인했다.
- DB 마이그레이션의 RLS, 함수 실행 권한, 관리자 역할, 정지·해제 감사, 계정 삭제 익명화와 설정 저장 경계를 검사했다. PGlite의 실제 PostgreSQL 실행 및 별도 실제 Supabase 통합 테스트로 권한과 집계를 검증했다.
- 타일 병합·장애물·능력 상태·공격 대기 규칙을 확인했다. 결정적 난수 보드 10,000개 × 4방향, 40,000개 경우에서 숫자 합계 보존, 좌표 중복·범위, 고정 타일, 입력 불변성, 이동 가능 여부 일치를 추가 확인했다.
- 서버 구조는 현재 한 프로세스에 맞는다. Redis나 새로운 저장소를 도입하지 않았으며, 다중 서버 전환은 별도 설계가 필요하다.

코드·TypeScript·React·보안 검토를 분리해 수행하고 수정 후 다시 검토했다. 검토와 테스트를 통과한 범위에서 추가로 재현된 결함은 없지만 모든 운영 장애나 악용 가능성이 없다는 뜻은 아니다.

## 의존성 보안

| 범위 | 점검 전 | 점검 후 |
|---|---:|---:|
| 전체 audit 경고 | 69 (critical 2, high 48, moderate 19) | high 1 |
| 운영 의존성 `pnpm audit --prod` | 별도 비교값 미기록 | 0 |

Socket.IO의 engine/parser, `ws`, 이미지 처리 `sharp`, CSS 처리 `postcss`, `shell-quote` 및 호환 가능한 전이 의존성을 갱신했다. 상위 패키지가 구버전을 고정한 항목만 워크스페이스 override로 지정했고, 깨끗한 frozen install·두 앱 빌드·소켓 Docker 실행으로 조합을 확인했다.

남은 경고는 ESLint 경로의 개발 의존성 `braces@3.0.3`이다. [권고 GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)는 수정 버전을 `>=3.0.4`로 표시하지만, 점검 시 npm 레지스트리의 최신 버전은 3.0.3이고 3.0.4는 게시되지 않았다. 존재하지 않는 버전을 강제하거나 경고를 숨기지 않았다. 수정 버전이 실제 게시되면 해당 의존성을 갱신하고 린트·빌드를 다시 확인해야 한다. 이 경고 때문에 전체 `pnpm audit`는 여전히 실패 종료한다.

Git에 들어갈 텍스트 파일의 secret/private key/서버 권한 JWT 패턴도 검사했다. 서버 `.env`, 웹·관리자 `.env.local`, Supabase 임시 파일은 제외된다. 공개 URL과 예제 환경 변수는 유지한다. 이는 정적 검사이며 과거에 외부로 공유된 키를 무효화하지는 않는다.

단위·DB 109개, 실제 Supabase 통합 1개, 브라우저 24개로 총 134개가 통과했다. 새 브라우저 회귀 검사 3개는 설정 재시도 연결 유지, 저장소·hydration, 키보드·터치를 다룬다. 기존 테스트의 서버 fixture에 빠진 `ability`, `skinId`, `serverTime`을 보완했고, viewport 변경 직후에는 실제 타일 전환 애니메이션 종료 후 너비를 측정하도록 했다. 기존 overflow·44px 터치 영역 검증을 유지했고 종료 시 route 정리가 원래 실패를 가리지 않도록 수정했다.

브라우저 검사에는 Chrome과 외부 도구 런타임의 Playwright를 사용했다. 웹 개발 서버가 `http://[::1]:3001`에서 실행 중이어야 한다. 저장소에 새 브라우저 의존성을 추가하지 않았다.

```sh
NODE_PATH=/path/to/playwright-runtime/node_modules \
  node --import ./apps/socket/node_modules/tsx/dist/loader.mjs \
  --test --test-concurrency=1 apps/web/tests/*.browser.mjs
```

브라우저 계정 fixture를 사용하는 검사와 실제 DB 검사를 구분했다. 실제 Supabase 검사에서는 랭크 경기, Elo 정확히 한 번 반영, RLS, Realtime 구독, 관리자 통계, 정지·해제 및 감사를 검증했다. 프로덕션 빌드는 실행 중인 개발 서버의 `.next`를 덮어쓰지 않도록 별도 복사본에서 수행했다.

## 남은 문제·운영 조건

1. **운영 배포 전 Fly 영구 볼륨 확인:** 설정 파일만으로 볼륨이 생성되지 않는다. `dfw`의 `results` 볼륨과 서버 1개를 준비하고, 기존 미전송 outbox 파일이 있으면 새 경로로 옮긴 뒤 배포해야 한다. [배포 절차](deployment.md)
2. **프로세스 메모리의 게임 상태:** 서버 재시작 시 진행 중 게임이 끝난다. 공유 상태·판정 조율 없이 인스턴스를 늘리면 안 된다.
3. **디스크 장애의 내구성 한계:** 디스크 쓰기가 실패한 상태에서 프로세스까지 종료되면 아직 파일에 기록되지 않은 결과는 복구할 수 없다. `/health`는 생존 검사이며 DB·디스크의 건강을 보장하지 않는다. outbox 로그와 디스크 여유 공간을 감시해야 한다.
4. **개발 의존성 보안 경고 1건:** 위 `braces` 권고는 수정 버전 게시 후 재검증이 필요하다.
5. **외부 공급자와 기기 검증:** 실제 운영 도메인·Vercel/Fly 배포, 이메일 전달·Google OAuth 공급자 설정, 실물 휴대폰·스크린리더, 장시간 부하·능력 밸런스는 이번 점검에서 확인하지 않았다. 원래 타일 색상의 전체 대비 보장은 하지 않는다.

코인 지급·차감·구매와 정식 솔로 모드는 기존 기획 보류 상태를 유지했다. 이전 UI 검증의 스크린샷·기록은 `docs`에 보존했다.
