# 업적왕과 일일 퀘스트

2026-10-17 기준. 업적은 `/achievements`, 일일 퀘스트는 대시보드 `/`에서 확인한다.

## 업적왕

- 초기 규칙은 다른 업적 5개 달성 시 `achievement-king` 업적과 같은 ID의 전용 프로필 아이콘을 영구 해금한다. 현재 목표·공개 상태는 관리자 카탈로그를 따른다.
- 한 번이라도 공개된 카탈로그 업적 중 `metric`이 `achievements`가 아닌 해금만 집계한다. 이미 보관된 업적도 포함하고, 업적왕 등 모든 컬렉션 업적은 제외한다. 아직 공개되지 않은 초안은 포함하지 않는다.
- `achievement_unlocks`의 컬렉션 삽입 트리거가 출석·대전·랭크·싱글 업적을 반영한다. `sync_achievements()`도 새 규칙을 평가하며 기존 달성자는 통합 마이그레이션으로 소급 해금한다. 중복 삽입과 컬렉션 보상 간 연쇄 해금은 발생하지 않는다.
- 장착 권한은 DB에서도 확인한다. 미달성 계정은 아이콘을 요청하거나 설정을 직접 수정해도 장착할 수 없다.
- 업적 화면은 총 달성 개수, 가장 진행률이 높은 다음 목표, 전체·도전 중·달성 완료 필터를 제공한다. 시간 업적은 실제 최고 기록과 목표 시간을 표시한다.

## 일일 보상

| 퀘스트 | 조건 | 보상 |
| --- | --- | --- |
| 오늘도 출석 | 로그인 계정으로 오늘 출석 | 20코인 |
| 하루 세 판 | 오늘 유효 대전 3판 완료 | 60코인 |
| 오늘의 승리 | 오늘 유효 대전 1승 | 40코인 |

- 한국 시간 자정에 새 퀘스트가 시작한다. 하루 최대 120코인이다.
- 대시보드를 열거나 진행도를 갱신할 때 완료한 보상이 자동 지급된다. 별도 수령 버튼은 없다. 대시보드는 30초 주기와 대전 기록 변경 시 갱신한다.
- 출석은 자동 출석 기록을 사용하며 다음 대시보드 갱신에서 반영한다. 출석보다 퀘스트 조회가 먼저 끝난 경우 다음 갱신까지 보상이 표시되지 않을 수 있다.
- 대전은 `matches.achievement_eligible`인 저장된 일반전·랭크전만 집계한다. 친구전, 게스트 상대, 동일 계정 대전, 싱글은 제외한다. 서버에서 확정한 기권 결과도 기존 업적과 같은 기준으로 포함한다.
- 경기 종료일로 집계한다. 자정 이후 저장된 전날 경기나 전날 미수령 보상은 소급 지급하지 않는다. 이미 지급된 코인은 날짜가 바뀌어도 남는다.

## 지급과 권한

`sync_daily_quests()`는 인자 없이 로그인 계정과 DB 시간을 사용한다. 브라우저는 계정 ID, 날짜, 진행량, 보상 금액을 지정할 수 없다.

`daily_quest_rewards`의 `(player_id, quest_day, quest_id)` 기본키가 재조회·동시 요청의 중복 지급을 막는다. 구매와 동일한 지갑 행 잠금을 사용하고, 지급 기록과 잔액 증가는 같은 트랜잭션으로 처리한다. 잔액 갱신 실패 시 지급 기록도 롤백된다. 계정 삭제 시 지급 기록도 삭제된다.

인증 계정은 자신의 지급 기록만 읽는다. 직접 INSERT·UPDATE·DELETE, 익명 계정과 정지 계정의 지급 요청은 거절된다. 테스트용 날짜를 받는 헬퍼는 private 스키마에 있으며 클라이언트와 service_role의 실행 권한이 없다.

## 배포와 복구

초기 구현 파일은 `20261017150000_daily_quests_and_achievement_king.sql`과 `20261017150001_backfill_achievement_king.sql`이다. **이미 콘텐츠 카탈로그가 적용된 DB에 이 두 파일을 다시 실행하지 않는다.** 정적 제약과 고정 업적왕 트리거는 후속 카탈로그 규칙으로 대체됐다.

기존 환경의 업그레이드는 실제 적용 이력을 확인한 뒤 `20261017180000_integrated_solo.sql` → `20261017180001_integrated_daily_catalog.sql` → `20261017180002_attendance_portrait.sql` 순서를 따른다. 대상 환경에 콘텐츠 카탈로그가 없으면 먼저 해당 마이그레이션이 필요하다. `180001`은 일일 지급·컬렉션 규칙·기존 달성자 해금을 연결한다. 아이콘을 업로드하고 소켓·웹을 배포하는 절차는 [배포 가이드](deployment.md)와 [환경별 통합 이력](full-performance/integration.md)을 따른다.

운영 규모의 스테이징 복사본에서 소급 해금 시간을 확인한다. 로컬 PGlite 테스트는 운영 데이터 규모의 잠금 시간을 보증하지 않는다.

복구는 전진 마이그레이션으로 `sync_daily_quests()`의 authenticated 실행 권한을 회수하고 새 대시보드 섹션을 비활성화한다. 이미 지급한 코인과 해금한 프로필, 지급 기록은 삭제하거나 차감하지 않는다. 카탈로그를 포함한 이전 앱 전체로 되돌리면 새 아이콘을 인식하지 못하므로 새 아이콘 정의는 유지한다.

## 확인

- `pnpm --filter socket exec tsx --test tests/daily-quests.test.ts tests/achievement-catalog.test.ts`
- `pnpm --filter socket exec tsx --test tests/integrated-migrations.test.ts` — 기존 카탈로그·배포 이력과의 통합, 컬렉션 규칙과 데이터 보존.
- `node --test apps/web/tests/daily-quests.browser.mjs` — 기존 브라우저 테스트와 동일하게 Playwright 런타임과 웹 개발 서버 필요.
- DB 테스트: 날짜 경계, 중복 지급, 권한·계정 격리, 구매 후 재조회, 지급 실패의 원자성, 과거 업적 소급 및 장착 제한.
- 브라우저 테스트: 자동 출석 보상, 실패·재시도, 모바일 진행도, 업적 필터와 프로필 장착. 가상 계정으로 실행하며 원격 계정은 변경하지 않는다.
