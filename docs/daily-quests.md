# 업적왕과 일일 퀘스트

2026-10-17 기준. 업적은 `/achievements`, 일일 퀘스트는 대시보드 `/`에서 확인한다.

## 업적왕

- 기존 업적 중 5개를 달성하면 `achievement-king` 업적과 같은 ID의 전용 프로필 아이콘을 영구 해금한다.
- 업적왕 자체와 준비 중인 업적은 5개 집계에 포함하지 않는다. 기존 달성자도 별도 데이터 마이그레이션으로 해금한다.
- `achievement_unlocks`의 삽입 트리거가 판정하므로 출석, 대전, 싱글에서 얻은 업적이 모두 반영된다. 중복 삽입은 보상을 복제하지 않는다.
- 장착 권한은 DB에서도 확인한다. 미달성 계정은 아이콘을 요청하거나 설정을 직접 수정해도 장착할 수 없다.
- 업적 화면은 총 달성 개수, 가장 진행률이 높은 다음 목표, 전체·도전 중·달성 완료 필터를 제공한다. 시간 업적은 실제 최고 기록과 목표 시간을 표시한다.

## 일일 보상

| 퀘스트 | 조건 | 보상 |
| --- | --- | --- |
| 오늘도 출석 | 로그인 계정으로 오늘 출석 | 20코인 |
| 하루 세 판 | 오늘 유효 대전 3판 완료 | 60코인 |
| 오늘의 승리 | 오늘 유효 대전 1승 | 40코인 |

- 한국 시간 자정에 새 퀘스트가 시작한다. 하루 최대 120코인이다.
- 대시보드를 열거나 진행도를 갱신할 때 완료한 보상이 자동 지급된다. 별도 수령 버튼은 없다. 대시보드는 30초 주기와 대전 기록 변경 시 갱신한다.
- 출석은 기존 자동 출석 기록을 사용한다. 로그인 직후 출석 처리가 완료되면 퀘스트도 다시 확인한다.
- 대전은 `matches.achievement_eligible`인 저장된 일반전·랭크전만 집계한다. 친구전, 게스트 상대, 동일 계정 대전, 싱글은 제외한다. 서버에서 확정한 기권 결과도 기존 업적과 같은 기준으로 포함한다.
- 경기 종료일로 집계한다. 자정 이후 저장된 전날 경기나 전날 미수령 보상은 소급 지급하지 않는다. 이미 지급된 코인은 날짜가 바뀌어도 남는다.

## 지급과 권한

`sync_daily_quests()`는 인자 없이 로그인 계정과 DB 시간을 사용한다. 브라우저는 계정 ID, 날짜, 진행량, 보상 금액을 지정할 수 없다.

`daily_quest_rewards`의 `(player_id, quest_day, quest_id)` 기본키가 재조회·동시 요청의 중복 지급을 막는다. 구매와 동일한 지갑 행 잠금을 사용하고, 지급 기록과 잔액 증가는 같은 트랜잭션으로 처리한다. 잔액 갱신 실패 시 지급 기록도 롤백된다. 계정 삭제 시 지급 기록도 삭제된다.

인증 계정은 자신의 지급 기록만 읽는다. 직접 INSERT·UPDATE·DELETE, 익명 계정과 정지 계정의 지급 요청은 거절된다. 테스트용 날짜를 받는 헬퍼는 private 스키마에 있으며 클라이언트와 service_role의 실행 권한이 없다.

## 배포와 복구

앱 배포 전에 다음 두 파일을 순서대로 적용한다.

1. `20261017150000_daily_quests_and_achievement_king.sql`
2. `20261017150001_backfill_achievement_king.sql`

첫 파일은 스키마·함수·트리거, 두 번째는 기존 달성자 해금을 담당한다. 운영 규모의 스테이징 복사본에서 업적 제약 변경과 소급 해금 시간을 확인한 뒤 배포한다. 로컬 PGlite 테스트는 운영 데이터 규모의 잠금 시간을 보증하지 않는다.

복구는 전진 마이그레이션으로 `sync_daily_quests()`의 authenticated 실행 권한을 회수하고 새 대시보드 섹션을 비활성화한다. 이미 지급한 코인과 해금한 프로필, 지급 기록은 삭제하거나 차감하지 않는다. 카탈로그를 포함한 이전 앱 전체로 되돌리면 새 아이콘을 인식하지 못하므로 새 아이콘 정의는 유지한다.
