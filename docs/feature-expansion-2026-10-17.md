## 검증 환경과 범위

Node.js 26, pnpm 11.1.3, Chrome/Playwright, Next.js 개발 서버를 사용했다. 게임 주소는 이 PC의 IPv6 `http://[::1]:3001`이다. 관리자 브라우저 테스트와 프로덕션 빌드는 임시 복사본에서 실행한다. 프로덕션 빌드를 실행 중인 개발 서버의 `.next`에 쓰지 않는다.

- `pnpm test`: **129개 통과**(소켓·게임·SQL·복구 저장소 127개, 언어 2개). PGlite에서 모든 실제 마이그레이션을 적용한다.
- 실제 PostgreSQL 17 동시성 테스트: **1개 통과**. 서로 다른 연결에서 중복 결과 6개, 결과→전환·전환→늦은 결과의 잠금 순서, 중복 관리자 전환, 새 시즌 투영 보존을 검사한다. `pg_stat_activity`에서 실제 advisory lock 대기를 확인한다.
- 게임 브라우저 전체 38개를 실행했다. 첫 실행 36개 통과, 오디오 타이밍 대기 1개와 이전 티어 fixture 1개가 실패했다. 오디오는 단독 재실행에 통과했고, fixture는 획득 티어 계약에 맞춰 수정했다. 수정 후 오디오·프로필·랭크 7개 재실행이 모두 통과했고, 최종 복구 브라우저 12개도 통과했다. 추가된 복구 3개를 포함한 최종 고유 테스트는 **게임 41개·관리자 1개**이며 전체 실행과 변경 부분 재실행을 합친 결과다.
- 어드민 브라우저는 격리한 Next 앱과 로컬 가상 인증/소켓 서버에서 실제 UI·서버 프록시를 실행한다. 실제 서비스 계정이나 운영 데이터를 수정하지 않는다.
- 인증·랭크 UI의 Supabase 응답은 가상 서버/브라우저 라우트로 제어한다. 따라서 실제 이메일 수신·호스팅된 Supabase의 복구 만료 설정을 검증했다는 뜻은 아니다.

독립 코드 검토에서 발견한 이전 시즌 대기열 점수와 일반전 대기 간섭, 신규 계정의 Gold 오표시, 복구 후 다른 계정 로그아웃 경쟁을 수정했다. 보안 검토에서 발견한 운영 API 인증 요청 제한 누락도 수정하고 회귀 테스트를 추가했다. `pnpm audit --prod` 취약점은 0개였다.

최종 `pnpm typecheck`, `pnpm lint`, 게임 웹·관리자 프로덕션 빌드와 `git diff --check`도 통과했다. 보안 재검토에서 실제 IPv6 콜백의 외부 경로·헤더 삽입·과도한 길이 경계 4건을 추가 확인했다. 코드·보안 재검토에 남은 확정 지적은 없다.

## 실행 명령

```sh
pnpm test
pnpm typecheck
pnpm lint

# Playwright가 설치된 경로를 NODE_PATH에 지정한다.
NODE_PATH=/path/to/playwright/node_modules node \
  --import ./apps/socket/node_modules/tsx/dist/loader.mjs \
  --test --test-concurrency=1 apps/web/tests/*.browser.mjs
NODE_PATH=/path/to/playwright/node_modules node --test apps/admin/tests/admin-expansion.browser.mjs

# 저장소 의존성을 변경하지 않는 선택적 실제 PostgreSQL 검사.
rank_runtime=$(mktemp -d)
npm install --prefix "$rank_runtime" embedded-postgres@17.10.0-beta.17 pg
NODE_PATH="$rank_runtime/node_modules" node --test apps/socket/tests/rank-concurrency.integration.mjs
```

PostgreSQL 검사는 임시 데이터 디렉터리와 임의 포트를 만들고 종료 시 정리한다. 프로젝트의 DB 환경변수나 원격 DB에 연결하지 않는다. 바이너리 다운로드가 필요한 첫 실행은 이후 실행보다 오래 걸릴 수 있다.

## 코드 정리

- 꾸미기와 상점의 보드 미리보기를 기존 구현에서 하나의 `SkinPreview`로 추출했다.
- 배치·승급 표시에는 공통 `RankProgress`를 사용하고, 홈·순위표·대전·결과·관리자·fixture를 새 획득 티어 계약으로 맞췄다.
- 관리자 조회·시간·목록 복귀와 운영 상태 처리는 기존 앱 구조 안에서 공유한다. 결과 저장 outbox와 인증 경계는 기존 동작을 유지했다.
- 실행용 의존성은 추가하지 않았다. 사용하지 않는 지급·구매 서버 코드와 자동 시즌 스케줄러도 만들지 않았다.

## 적용 전 남은 운영 작업

1. DB 백업 후 `20261017010000_admin_expansion.sql`, `20261017020000_rank_seasons.sql`을 순서대로 적용하고 웹·소켓·관리자를 배포한다. **새 앱은 새 DB 열을 요구하므로 DB 적용이 먼저다.**
2. 관리자 서버의 `ADMIN_SOCKET_URL`과 Supabase의 비밀번호 복구 Redirect URL을 설정한다.
3. 실제 이메일로 복구를 확인하고 운영 계정의 현재 시즌·배치·경기 저장을 확인한다. 시즌 종료는 관리자 화면에서 별도로 검토한 뒤 실행한다.

이번 작업은 원격 DB 마이그레이션, 실제 시즌 초기화, 운영 배포를 실행하지 않았다. 실기기·스크린리더·대규모 부하·장기 랭크 밸런스는 별도 확인이 필요하다.
