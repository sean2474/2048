# 버그 제보·피드백

- 게임 웹 `/feedback`: 게스트와 로그인한 사용자 모두 유형·제목·상세 내용을 작성한다. 헤더와 `/settings`에서 이동할 수 있다.
- 소켓 서버 `POST /feedback`: 입력 크기와 스키마, 허용 출처, 전달된 계정 토큰을 검증한다. 같은 요청 ID를 재전송해도 중복 저장하지 않는다. 실패하면 폼 내용을 유지하고 재시도할 수 있다.
- 관리자 앱 `/feedback`: 최신순 25개씩 표시한다. 로그인한 제보자는 기존 플레이어 상세 화면으로 연결한다. 게스트와 삭제된 계정은 계정 링크를 표시하지 않는다.
- `20261015171349_feedback.sql`: 서버 전용 키로만 저장하며 `is_game_admin()` 권한을 가진 관리자만 읽는다. 계정 삭제 시 제보자 연결만 제거한다.

서버의 기존 Supabase 환경 변수를 사용한다. 새 환경에서는 마이그레이션을 적용하고 소켓 서버도 새 코드로 재시작해야 한다. 데이터베이스 저장이 성공한 경우에만 접수 완료를 표시한다.

요청 제한은 현재 단일 서버의 연결 IP 기준 분당 5회다. Fly에서는 플랫폼의 `Fly-Client-IP`, 직접 실행에서는 TCP 상대 주소를 사용한다. 다른 프록시를 추가할 때는 신뢰 경계와 클라이언트 주소 전달을 다시 확인한다. 임의의 전달 헤더는 신뢰하지 않는다. 첨부파일, 이메일 발송, 관리자 답변·처리 상태는 이번 범위에 포함하지 않는다.

검증: 입력 경계·계정 확인·실패 응답·요청 제한 HTTP 테스트, PostgreSQL RLS·중복 방지·계정 삭제 테스트, 실제 게스트 제보→DB 저장→임시 관리자 목록 확인. 검증용 계정과 제보는 확인 후 제거한다.
