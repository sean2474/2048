# 전 페이지 로컬 측정 결과

기능 통합 기준 `e1052c7`과 최적화된 `a6327c1`을 같은 Apple M5 Max·Chrome 155 환경에서 비교했다. 실제 측정 checkout은 각각 `f80930e`/`e549464`이며, 제품 기준과 다른 커밋은 측정 코드·문서에 해당한다. before의 관리자·게임 측정에는 이전 harness `8776b8e`를 사용했다. 원본 JSON의 provenance에 실행 구간과 차이를 기록했다.

이 기준에는 앞선 웹 최적화 `3b0de17`의 홈·전적·랭킹·매치 찾기 서버/클라이언트 분리가 이미 포함된다. 따라서 이번 수치는 통합된 기능 위에 추가한 전 페이지·런타임 최적화의 차이다. 최초의 전체 클라이언트 웹사이트와 직접 비교한 결과가 아니다.

각 버전에서 웹·관리자 37개 페이지 템플릿을 다뤘다. 일반 페이지 36개는 데스크톱/모바일 에뮬레이션·cold/warm 각각 5회로 총 720회, `/play/[id]`는 실제 두 브라우저 대전으로 검증했다. 실제 앱 링크 이동 155회, 자연 종료/항복 대전 4회, 싱글 타이머 2회도 각각 통과했다. 실패는 없다. 인증이 필요한 데이터 페이지는 서버와 브라우저가 같은 가상 계정을 사용했다.

## 로딩과 번들

아래는 각 앱·화면 크기의 cold 전체 샘플 중앙값이다. 페이지별·warm 결과와 원본 값은 [전체 비교](comparison.md)에 있다. 모든 페이지가 빨라졌다는 결과는 아니다. 작은 로컬 시간 차이에는 측정 변동이 포함된다.

| 앱 / 화면 | load 이전 → 이후 | FCP 이전 → 이후 |
|---|---:|---:|
| 웹 / 데스크톱 | 43.0 → 39.6 ms | 40 → 44 ms |
| 웹 / 모바일 에뮬레이션 | 41.6 → 37.9 ms | 40 → 40 ms |
| 관리자 / 데스크톱 | 50.8 → 42.0 ms | 60 → 56 ms |
| 관리자 / 모바일 에뮬레이션 | 49.3 → 40.8 ms | 56 → 40 ms |

웹의 초기 gzip JS는 대체로 유지됐다. 홈 261,441→261,438 bytes, 설정 264,015→263,412 bytes, 상점 265,143→263,622 bytes, 솔로 270,431→269,514 bytes다. 대전은 274,746→274,966 bytes로 소폭 늘었다. 관리자 홈은 178,772→176,234 bytes, 경기 목록은 178,107→175,536 bytes다. 이는 초기 manifest의 고유 JS 파일을 개별 gzip한 합계이며, 지연 로딩 파일은 제외한다.

설정 조회는 웹 cold 전체 샘플 중앙값에서 데스크톱 3→2회, 모바일 에뮬레이션 2→1회다. 이 수치는 링크 prefetch의 서버 요청까지 포함한다. 요청 한 번 안의 중복 제거는 별도 runtime 회귀 테스트로 검증했다.

전체 측정의 LCP는 관찰 종료 시점이 달라 개선 결론에서 제외했다. [홈 추가 진단](home-lcp-diagnostic.md)은 동일한 최소 1초 관찰 구간에서 데스크톱 cold 372→356 ms, 모바일 cold 372→372 ms였다. 마지막 후보는 프로필의 시즌 설명 문단이었다. 실제 Speed Insights 점수나 현장 LCP 결과는 아니다.

## 게임과 시간 정확도

최적화 후 실제 로컬 소켓 서버와 두 브라우저로 진행했다. 입력은 유효한 이동 중 즉시 합산 점수가 낮은 방향을 번갈아 선택하고 최소 100 ms 간격을 뒀다. 보드나 종료 조건을 주입하지 않았다.

| 측정 | 데스크톱 | 모바일 에뮬레이션 |
|---|---:|---:|
| 자연 종료까지 입력 수 | 503 | 504 |
| 실제 플레이 시간 | 51.20초 | 51.28초 |
| 서버 방 전체 시간, 연출 포함 | 54.43초 | 54.52초 |
| 입장 시작 → 보드 확인 | 3.446초 | 3.352초 |
| 그중 의도된 소개 연출·입장 | 3.234초 | 3.232초 |
| 입력 → 화면 반영 중앙값 | 42.6 ms | 47.7 ms |
| 종료 패킷 → 결과 오버레이 DOM 확인 | 10.9 ms | 13.4 ms |
| 별도 항복 패킷 → 종료 패킷 | 0.6 ms | 12.1 ms |
| 싱글 화면 시계 오차, 약 5초 구간 | 13.6 ms | 9.6 ms |
| 싱글 서버 시계 오차, 같은 구간 | 14.5 ms | 15.7 ms |

자연 대전은 실제 잠긴 보드로 끝났다. 플레이 길이는 무작위 타일과 자동 입력 정책에 좌우되므로 최적화 효과나 사람의 평균 경기 시간으로 해석하지 않는다. 입력 화면 반영 중앙값은 이전 42.6/48.0 ms와 거의 같았다. 관전은 실제 진행 중인 상대 보드까지 확인했다. 위 오버레이 시간은 DOM 배치 확인까지이며 전체 등장 애니메이션 완료 시간이 아니다. 항복은 자연 종료와 별도로 측정했고, 이전 confirmation 자동화 시간과 이후 패킷 시간을 비교하지 않았다.

로컬 데이터 API는 fixture다. 소켓 패킷 간격은 실제 loopback 통신과 브라우저 자동화 관찰 비용을 포함한다. 모바일은 실제 휴대폰이 아니라 데스크톱 CPU의 터치·화면 에뮬레이션이다. 운영 네트워크/DB 지연, 클라우드 cold start, 실제 휴대폰, 현장 Speed Insights는 이 결과로 검증한 것이 아니다. 배포 환경 측정은 별도 기록한다.

원본: [before](before/raw.json), [after](after/raw.json). 당시 모든 페이지 스크린샷은 측정 worktree에 보관하고 대표 화면은 저장소에 포함했다. 2026-10-23 정리에서 직접 참조되지 않은 캡처·빌드 로그는 제거했으며 [정리 전 Git 기록](https://github.com/sean2474/2048/tree/46d8e38d1fb95e15aac8780cc0b81aeacd6c2363/docs/full-performance)에서 확인할 수 있다. 원본 JSON과 측정 수치는 보존한다. 첫 게임 결과 캡처는 등장 애니메이션 중간 프레임이어서 대표 화면에서 제외했다.

실제 배포된 staging·production의 비공개 친구방 측정은 [배포 대전 결과](remote-results.md)에 별도로 기록했다.
