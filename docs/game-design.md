# 2048 Duo 게임 설계와 구현 범위

최종 갱신: 2026-10-23 · **5×5 멀티 대전·능력 5종과 4×4 싱글플레이를 제공한다.**

## 현재 게임

멀티 대전은 5×5 보드에서 숫자를 합쳐 성장하고, 256·512 병합으로 상대에게 장애물을 자동으로 보내는 1대1 2048이다. 자동 방어력은 없다.

| 모드 | 참가 방식 | Elo 반영 |
|---|---|---|
| 온라인 일반전 | 게스트 또는 로그인 계정, 일반전 대기열 | 없음 |
| 온라인 랭크전 | 서로 다른 로그인 계정, 레이팅 기반 대기열 | 있음 |
| 친구 대전 | 여섯 자리 방 코드 또는 온라인 친구의 대전 신청 수락 | 없음 |
| 싱글 타임어택·무한모드 | 게스트 또는 로그인 계정, 4×4 보드 | 없음 |

세 멀티 모드의 이동·공격·승패 규칙은 같다. 일반전과 랭크전은 서로 매칭되지 않는다. 싱글은 공격·능력 없이 진행하며 별도 기록과 보상 규칙을 사용한다. 아래 자동 공격·승패·연결 규칙은 멀티 대전 기준이다.

## 자동 공격과 장애물

| 새로 합쳐 만든 타일 | 효과 |
|---|---|
| 128 | 일반 병합만 수행 |
| 256 | X 블록 1개 자동 발사 |
| 512 | 하드블록 1개 자동 발사 |
| 1024 | 승리. 자동 방어 없음 |

- X는 이동하지만 병합되지 않는다. 하드 블록은 고정되어 이동 경로를 나눈다.
- 해당 값으로 **새로 병합된 타일**만 공격한다. 기존 타일 이동은 다시 공격하지 않으며 512 병합은 X를 추가 발사하지 않는다. 한 이동에서 여러 개를 만들면 각각 발사한다.
- 일반 공격은 보유하거나 수동 발사하지 않는다. 누적 발사 수는 경기 상태와 통계에 기록한다.
- 수신자는 종류별 공격 예고 이펙트를 본다. 공격은 수신자의 다음 유효한 이동·병합 뒤, 일반 타일 생성 전에 빈칸에 배치된다. 빈칸이 부족하면 나머지는 계속 대기한다.
- 도착 예정 공격은 합계 최대 6개다. 동시에 발생한 공격은 X부터 하드블록 순서로 채우고, 대기열 한도를 넘는 추가 공격은 버린다.
- 무효 이동은 자동 공격·공격 배치·일반 타일 생성을 발생시키지 않는다. 승패가 결정된 이동에서는 추가 자동 공격을 보내지 않는다.
- 자동 방어는 없다. 기본 능력 X 제거로 X 1개를 제거할 수 있다. 특수 능력만 기본 스페이스바나 내 보드 아래 버튼으로 직접 사용하며, 키 설정에서 바꾸거나 문자 단축키를 끌 수 있다.

도착 대기 한도 6개는 첫 플레이 테스트를 위한 초기 밸런스 값이다.

## 승패와 연결

- 양쪽은 같은 초기 보드로 시작한다. 이동과 승패는 서버가 판정한다.
- 1024를 만들면 승리하며, 이동 불가 판정보다 우선한다. 그 외에는 이동 불가인 플레이어가 패배하고 양쪽 모두 이동 불가면 무승부다.
- 항복은 즉시 패배한다. 연결이 끊기면 양쪽 게임을 멈추고 30초 동안 재접속을 기다린다. 시간 초과는 패배다.
- 재접속 시 보드·누적 발사 수·도착 예정 공격을 그대로 복원한다.
- 경기 종료 후 같은 모드로 다시 플레이할 수 있다.

현재 플레이 시간 비교를 위해 승리 목표는 임시로 1024이며, 결과는 `reached_1024`로 기록한다. 현재 코드와 DB 제약은 이전 `reached_2048` 승리 사유를 허용하지 않는다. `20261017050000_current_win_reason.sql`은 현재 승리 사유만 허용하고 기존 경기·보상 데이터를 변경하지 않는다. 예상하지 못한 이전 승리 사유의 행이 있으면 데이터를 삭제하지 않고 적용에 실패한다. 이 파일은 기존 전환 이력이며 이미 적용한 마이그레이션은 수정·재실행하지 않는다. 이후 프로토콜 변경은 구형 클라이언트와의 호환성을 확인하고 [배포 가이드](deployment.md)의 순서를 따른다.

## Elo 기반 티어

공개 레이팅 하나를 매칭과 티어에 사용한다. 초기 레이팅은 1200, Elo 계수 K는 32다.

`기대 성적 = 1 / (1 + 10 ^ ((상대 레이팅 - 내 레이팅) / 400))`

`변동량 = round(32 × (경기 결과 - 기대 성적))`

경기 결과는 승 1, 무 0.5, 패 0이며 반대편은 부호를 바꾼 동일한 점수를 받는다. 점수와 최고 타일은 랭크 보너스에 반영하지 않는다.

| 티어 | 레이팅 |
|---|---|
| Bronze | 1000 미만 |
| Silver | 1000–1199 |
| Gold | 1200–1399 |
| Platinum | 1400–1599 |
| Diamond | 1600–1799 |
| Master | 1800 이상 |

- 랭크 매칭은 레이팅 차이 150 이내에서 시작한다. 둘 중 짧은 대기시간을 기준으로 10초마다 50씩 넓히되 최대 300을 유지하며, 가능한 상대 중 가까운 레이팅을 우선한다.
- 같은 로그인 계정은 기기·탭이 달라도 일반전·랭크전 대기열, 친구 방 코드 대기, 진행 중 멀티 경기를 통틀어 하나만 참여할 수 있다. 먼저 참가한 세션을 유지하고 두 번째 참가 요청은 `already_in_game`으로 거절한다. 모드를 바꿔도 제한하며 재접속 대기 중인 경기도 포함한다. 대기 취소·경기 종료 후 다시 참가할 수 있다.
- 이 제한은 멀티 참가 제한이다. 다른 기기의 웹 로그인을 해제하거나 같은 계정으로 다른 기기에서 솔로 이어하기를 막지는 않는다. 독립된 게스트 세션은 일반전·친구전에 함께 참여할 수 있다.
- 서버가 계정과 레이팅을 조회한다. 클라이언트가 보낸 임의 레이팅은 사용하지 않는다.
- 랭크 경기만 Elo에 반영한다. 일반전·친구전은 로그인 계정의 기록으로 저장하되 레이팅을 바꾸지 않는다.
- 기록에는 모드와 경기 전·후 레이팅, 변동량을 남긴다. 중복 결과는 한 번만 집계한다.
- 결과 저장이 지연되면 해당 계정의 다음 랭크 참가를 막아 계산 순서를 지킨다. 진행 중인 다른 멀티 경기가 없으면 일반전·친구전은 가능하다. 디스크에 남은 저장 대기도 재시작 시 먼저 복원한다.
- 기존 경기는 `legacy`로 보존하고 과거 승수를 Elo로 소급 변환하지 않는다.
- 랭크는 최초 10경기 평가를 마친 뒤 Elo 구간으로 티어를 즉시 결정한다. 승급전은 없으며 무승부도 점수·경기 수에 반영한다. 관리자가 시즌을 전환해도 Elo·현재 티어·평가 진행도는 유지한다. 시즌 전적과 최고 기록만 초기화하며 해당 시즌 10경기부터 순위표에 등재한다. 매칭은 양쪽 대기시간을 기준으로 허용 격차를 ±150에서 10초마다 50씩, 최대 ±300까지 확대한다. 자세한 규칙과 경계 상황은 [랭크 시즌](ranked-seasons.md)을 참고한다. 별도 LP와 반복 상대 제한은 없다.

초기 레이팅·K·티어 경계·매칭 허용 범위도 실제 대전 데이터를 보고 조정할 초기 값이다.

## 추가 기능과 범위

**싱글플레이:** 4×4 타임어택은 최대 1시간 안에 2048까지 걸린 시간을 겨룬다. 무한모드는 시간제한 없이 계속 진행하며 2048·4096·8192 보상을 제공한다. 서버가 판정하고 진행상황을 DB에 저장한다. 계정은 다른 기기에서도, 게스트는 같은 브라우저의 저장 토큰으로 이어간다. [싱글 규칙과 복원 범위](solo-time-attack.md)

**특수능력 구현:** X 1개 제거(기본), 숫자 생성 중지, 감속, 알박기, 상대 32 자리 바꾸기를 실전에 적용했다. 경기 전 1개 선택, 병합 점수 1024당 1회 충전, 최대 1회 보유. 재접속 시 효과와 충전을 복원한다. 세부 규칙과 한계는 [능력 설계](loadout-and-economy.md)를 따른다.

꾸미기 업적은 출석·유효 대전·랭크·싱글 기록과 다른 업적 달성 개수로 영구 보상을 해금한다. 업적왕의 초기 목표는 다른 업적 5개이며 현재 공개 조건과 보상은 DB 카탈로그를 따른다. 로그인 계정은 페이지 방문 시 한국 시간 기준 하루 한 번 자동 출석한다. 경기 업적은 서로 다른 비익명 계정 두 명의 서버 저장 일반전·랭크전을 집계한다. 시즌 전환이나 연속 출석 중단으로 이미 해금한 보상을 잃지 않는다. [세부 조건](achievements-and-shop.md)

코인 상점은 실제 잔액 차감과 영구 구매를 지원한다. 대시보드 [일일 퀘스트](daily-quests.md)는 출석·3판 완료·1승으로 한국 시간 하루 최대 120코인을 지급한다. 상품·가격·공개 상태는 [콘텐츠 카탈로그](content-catalog.md)로 관리하며 경기마다 코인을 주는 과거 초안은 구현하지 않았다. 친구 요청·메시지·대전 신청과 허용된 경기 관전은 [친구 기능](social.md)을 따른다. 실물 결제, 2대2, 신규 장애물, 생존 모드는 이번 범위 밖이다. 시즌 전환은 관리자 화면에서 수동 실행한다. 환경별 원격 적용·배포 상태는 [배포 가이드](deployment.md)를 따른다.

## 검증과 운영 한계

규칙·소켓·저장 복구·DB 권한 테스트와 브라우저 일반 대전에서 자동 발사·배치·능력 충전·재접속을 확인했다. 실제 Supabase에서는 테스트 계정 두 개로 랭크 결과, Elo 중복 방지, 기록·순위 Realtime을 검증했다.

현재 방과 매칭, 저장 대기 계정 차단은 소켓 서버 한 인스턴스 기준이다. 서버 재시작으로 진행 중 멀티 대전은 복원하지 않는다. 싱글은 마지막으로 성공한 DB 체크포인트에서 복원한다. 여러 인스턴스 운영, 실제 휴대폰·보조공학 기기 검증, 장기 밸런스 테스트는 별도 작업이다.
