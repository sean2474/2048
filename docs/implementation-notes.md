# 2026-10-15 구현 메모

> 날짜별 구현 이력이다. 수동 공격·무료 장비·준비 중 기능 등 과거 설명은 현재 동작이 아니다. 현재 구조는 [README](../README.md), [게임 규칙](game-design.md), [카탈로그](content-catalog.md)를 따른다.

- 문제: React effect가 gameState에 의존해 매 상태 패킷마다 소켓을 끊고 다시 열었다. 방 ID와 명시적 재시도만 연결 수명에 영향을 주도록 바꿨다.
- 문제: 소켓 ID를 플레이어 ID로 사용해 페이지 이동과 새로고침 때 상태를 옮겨야 했다. 탭별 임의 토큰의 서버 해시를 플레이어 ID로 사용하고 소켓 연결은 별도로 추적한다.
- 판정: 빈 칸이 있다는 사실만으로 이동 가능하다고 할 수 없다. 하드 블록에 갇힌 보드에서 실제 인접 이동/병합을 검사한다.
- 판정: 대기 중 공격은 일반 타일 생성보다 먼저 처리해야 풀 보드에서 합쳐도 공격이 영구 대기하지 않는다.
- 인증: Socket.IO 연결마다 Supabase getUser로 토큰을 검증하고 경기 중 계정 교체를 거절한다. 게스트는 기존 탭별 세션 토큰을 사용한다.
- 저장: 서버만 호출할 수 있는 record_match가 경기·참가자·통계를 한 트랜잭션으로 기록한다. 경기 UUID로 중복을 막고, 계정 UUID 순서로 잠가 동시 경기의 통계 갱신 교착을 피한다.
- 복구: 디스크 outbox에 먼저 기록하고 원격 성공 후에만 파일을 삭제한다. 30초 재시도와 재시작 복구를 지원하며 배포 시 영구 볼륨이 필요하다.
- 실시간: 보드/판정은 Socket.IO, 순위·기록은 Supabase Postgres Changes를 사용한다. 순위는 공개, 기록은 참가자에게만 보이며 임의 클라이언트 결과 쓰기를 차단한다.
- 원격 적용: Supabase 플러그인으로 players, matches, restrict_rls_event_trigger, ranked_elo 마이그레이션을 적용했다. 공개 스키마 테이블 5개 모두 RLS가 활성화돼 있고 결과 저장 함수는 service_role만 실행할 수 있다. 플랫폼의 RLS 이벤트 함수가 공개 실행 권한을 갖던 경고도 해소했다.
- 원격 검증: pnpm test:remote가 실제 계정 두 개로 로그인·소켓 대전·결과 저장·중복 방지·RLS·Realtime을 검사한 뒤 임시 데이터만 삭제한다. 이후 관리자 통계·일반 계정 접근 차단·정지와 해제·감사 기록까지 확장해 실제 테스트를 통과했다.
- Realtime 준비 상태: SUBSCRIBED는 채널 연결만 보장한다. postgres_changes의 system/ok 응답 뒤에 다시 조회해 DB 구독 준비 전 변경을 놓치는 구간을 닫는다.
- 공격 변경: 128 자동 발사를 제거했다. 새 256은 X, 새 512는 하드 공격권을 충전한다. 종류별 보유 3개, 이동 없이 연속 발사, 도착 대기 6개이며 발사와 실제 배치를 구분한다. 재접속은 보드·공격권·도착 예정 공격을 복원한다.
- 범위: 최신 사용자 결정에 따라 멀티만 구현했다. 솔로와 충전형 특수능력은 보류하고 설계 문서에 후보만 남겼다.
- 랭크: 일반전·랭크전·친구전 모드를 명시한다. 서버 조회 레이팅으로 별도 매칭하고 랭크전만 초기 1200, K=32 Elo를 적용한다. 과거 경기·통계는 보존하며 소급 변환하지 않는다.
- 저장 순서: 리뷰에서 이전 결과의 실패·재시도가 다음 경기 뒤에 적용되는 문제를 발견했다. outbox의 미저장 랭크 계정을 시작 전에 복원하고, 원격 저장 완료까지 새 랭크 참가를 막는다. 일반전·친구전은 계속 가능하다. 이 차단은 기존 서버 구조와 같이 한 인스턴스를 전제로 한다.
- 검증: 멀티 공격권 단계의 로컬 테스트 34개와 타입·린트·프로덕션 빌드를 통과했다. 관리자 추가 후 현재 로컬 테스트는 50개이며 모두 통과했다. 새 관리자 앱 분리 후 빌드·브라우저 검증은 아래 추가 기록을 따른다.
- 브라우저: 실제 일반 대전에서 256·512 충전과 수동 공격·배치·재접속·항복·재경기를 확인했다. 375px·1440px에서 넘침이 없고 공격 버튼은 48px 이상이다. 문자 단축키(WASD·1·2)를 끄는 옵션을 추가했다.
- 남은 확인: 실제 가입 확인 메일, 로그인한 브라우저의 랭크·기록, 실제 휴대폰·보조공학 기기, 장기 밸런스와 운영 배포. Socket.IO 의존성 보안 업데이트와 이후 검증 결과는 [2026-10-16 코드 점검](code-audit-2026-10-16.md)에 정리했다.

## 2026-10-16 관리자 분리와 연결 복구

- 구조: `apps/admin`을 별도 Next 앱으로 분리하고 게임 앱의 `/admin` 라우트를 제거했다. 공통 Button·AlertDialog는 `packages/ui`에서 사용한다. 로컬 게임 3001, 관리자 3100, 소켓 4000이다.
- 권한: 인증된 계정 UUID에 DB `admin_roles`를 부여한다. 관리자 화면과 각각의 SECURITY DEFINER RPC에서 권한을 확인한다. 사용자 metadata의 관리자 플래그는 사용하지 않는다.
- 통계: 유효 이동·실제 공격권 충전·수락된 발사·실제 장애물 배치를 종류별로 집계한다. 과거 미수집 결과는 NULL로 보존하고 0과 구별한다. 게스트 경기 역시 익명 결과로 집계한다.
- 정지: 새로운 일반전·랭크전·친구전만 막는다. 매칭 직전 상태를 재조회하고 조회 실패 시 인증 사용자의 신규 참가를 보류한다. 진행 중 대전·항복·재접속은 계속 가능하다. 사유·실행자·상태 변경을 원자적으로 기록하며 관리자 계정은 정지하지 못한다.
- 세션: 관리자 전용 쿠키와 별도 로그인 화면을 사용한다. 리뷰에서 게임 로그아웃의 기본 global 범위가 관리자 세션까지 취소하는 문제를 찾아 양쪽 모두 local 범위로 맞췄다. 관리자 로그인은 현재 이메일·비밀번호 방식이다.
- 연결 장애: 웹은 실행 중인데 소켓 실제 서버 자식 프로세스가 종료되어 있었다. watcher 부모는 살아 있어 실행 중으로 오인할 수 있었다. 소켓을 재실행해 복구했다. 당시 자식 종료 원인은 로그가 없어 확정하지 않았다.
- 개발 기동: `pnpm dev`는 웹·관리자·소켓을 함께 실행하고 하나가 종료되면 모두 종료한다. 이 명령의 소켓은 watcher 없이 실행하므로 서버 코드 수정 후 재시작한다. 별도 `dev:socket`에는 변경 감지를 유지한다. 기본 CORS에도 3001을 추가했다.
- UI: 기존 80px 기본 버튼을 40px로 정리하고 인증 폼은 44px 입력·8px 라벨 간격·16px 필드 간격·24/32px 패딩을 사용한다. 게임 보드 입력 규칙은 변경하지 않았다.
- 보안 진단: 관리자 테이블의 무정책 RLS는 직접 접근을 거부하기 위한 구성이다. authenticated 실행 가능 SECURITY DEFINER 관리자 RPC는 내부 권한 검사로 보호한다. 유출 비밀번호 보호 기능 비활성화 경고는 별도 Supabase 운영 설정으로 남아 있다.
- 브라우저 대전: 복구 후 서로 독립된 두 브라우저 컨텍스트에서 일반전과 친구전 모두 같은 방 진입, 타일 값·위치·점수 동기화, 항복 결과·모드별 재경기 링크를 확인했다.
- 최종 검증: 로컬 50개 테스트·전체 타입 검사·린트·게임 웹과 관리자 각각의 프로덕션 빌드를 통과했다. 브라우저에서 관리자 로그인·일반 계정 거부·필터·검색·정지/해제·감사 기록·키보드 확인창·양방향 로그아웃 분리를 확인했다. 관리자 375/768/1440px에서 가로 넘침이 없었다. [브라우저 QA](browser-qa.md)에 범위와 미검증 항목을 기록했고 테스트 계정·경기·감사 기록·임시 비밀번호 파일을 정리했다.

## 2026-10-16 게임 UI·설정·로드아웃

- 대시보드와 대전 찾기를 분리하고 한국어·영어를 공통 locale provider/앱별 사전으로 연결했다. 관리자 링크는 게임 헤더에서 제거했고 코인은 로그인한 사용자 아이콘 옆에만 표시한다.
- 실제 플레이 보드 대신 일시정지 가능한 CSS 대결 일러스트를 사용한다. 원래 숫자 타일·X·하드 색상과 모양은 유지했다.
- 대전은 가로·세로 가용 공간으로 정사각형 보드 크기를 계산한다. 내 보드 옆에 종류별 3칸 공격권을 표시하며, 모바일 상대 보드는 축소한다. 최소 높이 이하에서의 스크롤은 의도한 동작이다.
- `/settings`에서 언어·이동/공격 키·문자 단축키·닉네임·로그아웃·계정 삭제를 제공한다. DB 계정 설정 우선, 최초 행에만 게스트 쿠키 초기화, 로그아웃 시 게스트 복원을 적용했다. 세부 충돌 정책은 [설정 설계](settings.md)에 있다.
- 계정 삭제는 대전 서버에서 본인 인증·이메일 확인·관리자 보호·진행 중 경기와 저장 대기 확인 후 수행한다. 대기 매칭 콜백을 무효화하고 세션을 폐기한다. 기록 익명화와 지갑/설정 cascade를 실제 임시 계정으로 검증했다.
- 무료 스킨 3종을 보드에 연결하고 코인 지갑은 읽기 전용 0원으로 생성한다. 능력은 선택 화면과 10종 기획만 제공하며 효과·지급·구매는 구현하지 않았다. [기획](loadout-and-economy.md)
- 최신 자동·브라우저 확인과 미검증 항목은 [검증 기록](ui-refresh/validation.md) 및 [UI QA](ui-refresh/report.md)를 따른다.

## 2026-10-17 자동 공격과 능력 조작

- 최신 규칙은 256·512 병합 시 서버 자동 공격이며 공격권 보관·수동 발사 UI를 제거했다. 이전 날짜의 메모는 당시 구현 기록이다.
- 특수 능력만 내 보드 아래에서 수동 사용하고 기본 키는 스페이스바다. 키 설정에서 이동·능력 키와 단축키 활성화를 함께 저장한다.
- 상대 능력 아이콘·충전율, 자동 공격 발사·착탄 이펙트를 제공한다. 대시보드에서 5단계 튜토리얼로 진입한다.
- 양쪽 이름 왼쪽에 서버가 확인한 프로필 아이콘을 표시한다. 상단에는 모드 아이콘을 추가하고 하단 도착 예정 문구를 제거했다. 실전 방향패드는 모바일에서 유지하고 700px 이상에서는 숨긴다.
- 최종 로컬 검증: 단위·DB 171개, 브라우저 55개 항목을 확인했다. 브라우저 전체 실행은 54개 통과·1개 실패였고, 설정창 닫힘을 기다리지 않던 테스트를 수정해 해당 파일 3개를 재실행하여 모두 통과했다. 타입·린트와 운영 의존성 audit도 통과했다. 320/375/768/1024/1440px 렌더를 확인했다. 별도 채팅의 솔로 작업은 격리한 검증·배포 사본에 포함하지 않았다.
