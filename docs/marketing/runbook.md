# 촬영과 첫 2주 운영

이 문서는 실행안이다. **영상·캡처 파일을 새로 제작하지 않았고 게시 일정도 예약하지 않았다.** D1은 촬영·플레이 확인이 끝나고 사용자가 발행을 시작하는 날이다. 시간은 모두 KST이며 운영 가능한 시간을 정하기 위한 가설이다.

## 먼저 확보할 실제 소재

| ID | 소재 | 완료 기준 |
|---|---|---|
| V1 | 256 합성 → 상대 X 유입, 약 12~15초 | 두 보드와 원인·결과가 읽히고, 상대 유효 이동까지 보임 |
| V2 | 친구 방 진입 → 실제 대전, 약 15~20초 | 실제 메뉴 이름·코드 입력·두 보드가 연결됨 |
| S1 | X가 움직이지만 합쳐지지 않는 장면 | 실제 숫자 타일과 X 구분 가능 |
| S2 | 512 공격·고정 블록 | 보드 이동 후에도 블록이 고정된 것을 확인 가능 |
| S3 | 1024 생성·승리 화면 | 실제 승리 결과이며 다른 경기 결과를 붙이지 않음 |
| S4 | 4×4 솔로 화면 | 대전 보드와 혼동하지 않도록 모드 이름 포함 |
| S5 | 충전된 X 제거 능력 | X를 1개 제거한 뒤 막혔던 합성이 가능해지는 장면. X07은 이 장면을 확보했을 때만 사용 |

기존 `docs/abilities/live-clear-x.png`에는 예전 수동 공격 UI가, `docs/social/challenge-game-desktop.png`에는 예전 단축키·개발 배지가 있다. 현재 홍보용으로 재활용하지 않는다. 현재 코드의 OG 이미지는 링크 카드용 브랜드 그림으로만 사용한다.

촬영은 게스트 친구 방 두 클라이언트에서 한다. 공개 일반전에서 다른 사람을 촬영 대상으로 기다리게 하지 않는다. 방 생성 전후의 메뉴, 코드 입력, 대전 시작·종료가 정상인지 함께 확인한다. 이 절차는 이번 준비 작업에서 수행하지 않았다.

### V1 · “내가 256을 만들면”

| 시간 | 실제 화면 | 자막 |
|---|---|---|
| 0–2초 | 128 두 개가 합쳐져 256이 되는 순간부터 시작. 로고 인트로 없음 | `내가 256을 만들면` |
| 2–6초 | 상대 쪽 공격 예고, 상대가 유효 이동한 뒤 X가 들어오는 과정 | `상대 보드에 X가 갑니다` |
| 6–10초 | 상대가 움직이며 X가 이동하지만 합쳐지지 않는 모습 | `움직이지만 합쳐지진 않아요` |
| 10–15초 | 두 보드가 보이는 실제 화면 유지 | `2048 Duo` / `www.2048duo.io` |

촬영 시간이 길어지면 대기 구간을 잘라낼 수 있지만, 공격이 즉시 발생하거나 X가 다른 효과를 내는 것처럼 순서를 바꾸지 않는다. “내가 256을 만들면” 장면이 실제로 나오지 않으면 다른 캡처로 대체하지 말고 해당 버전을 보류한다. 내레이션 없이 자막과 게임 소리만으로도 이해되게 만든다.

### V2 · “코드 하나로 같이 시작”

| 시간 | 실제 화면 | 자막 |
|---|---|---|
| 0–2초 | 실제 대전 중인 양쪽 보드 | `친구랑 들어가는 법` |
| 2–6초 | `대전 찾기 → 친선전 → 방 만들기` | `한 명은 방 만들기` |
| 6–10초 | 다른 클라이언트에서 `방 참여하기`, 6자리 코드 입력 | `한 명은 코드로 입장` |
| 10–16초 | 입장한 두 사람이 실제로 이동·합성 | `친구전은 가입 없이` |
| 16–20초 | 플레이 화면과 게임명·도메인 | `2048 Duo · www.2048duo.io` |

코드가 보이는 영상은 방을 종료한 뒤 게시한다. 영상 길이는 편집안이지 실제 입장 소요 시간 약속이 아니다. “10초 만에 시작”이라는 성능 문구로 바꾸지 않는다.

### 편집·접근성

- X는 두 보드가 읽히는 가로 또는 정사각 구도, Shorts/Reels는 9:16 편집본을 제안한다. 세로로 잘라 상대 보드가 사라지면 두 보드 장면을 순서대로 확대하되 같은 경기임을 유지한다.
- 화면 하단의 플랫폼 UI와 자막이 겹치지 않게 미리보기로 확인한다. 작은 숫자가 읽히는지 실제 휴대폰에서도 본다.
- 자막은 배경과 충분히 구분되는 색으로, 한 번에 한 문장만. 무음으로 봐도 핵심 규칙이 전달돼야 한다.
- 색깔만으로 공격을 설명하지 않고 `X`·`고정 블록`을 자막에 쓴다. 빠른 섬광·과도한 화면 흔들림은 추가하지 않는다.
- 음원은 사용 권한이 확인된 것만 사용한다. 초기안은 실제 게임 소리만으로 충분하다. 합성 음성·생성 이미지·가짜 게임 장면은 필요 없다.
- 이미지 대체 텍스트 예시: `2048 Duo 대전 화면. 왼쪽에서 128 두 개가 256으로 합쳐지고, 상대의 다음 이동 뒤 오른쪽 보드에 X 장애물이 들어온다.` 실제 첨부 화면과 맞을 때만 쓴다.

X의 [공식 크리에이티브 안내](https://business.x.com/en/advertising/creative-best-practices)는 짧은 영상, 초반 움직임, 무음용 자막을 권한다. **광고용 가이드**이므로 자연 게시물의 노출 성과가 보장된다고 해석하지 않았다. 위 길이·구도는 이번 소규모 실험의 제작안이다.

## 14일 운영안

하루마다 새 글을 채우지 않는다. 핵심 자산을 준비하고 댓글에서 실제로 나온 혼란을 반영한다. 아래 시간은 최적 시간으로 검증된 값이 아니다. 같은 언어·비슷한 소재끼리 비교한다.

## 읽을 지표와 읽을 수 없는 지표

**처음 답할 질문:** 설명을 본 사람이 규칙을 이해하고, 직접 들어와 한 판을 끝낼 수 있는가? 노출 목표·전환율 목표를 근거 없이 정하지 않는다.

| 질문 | 현재 이용할 수 있는 근거 | 해석 제한 |
|---|---|---|
| 어떤 소재가 사람을 멈추게 하나 | 게시물 노출·영상 시청 지표·실제 댓글 | 서로 다른 플랫폼의 조회수를 같은 의미로 비교하지 않음 |
| 게임에 가려 했나 | 플랫폼이 제공하는 링크 클릭 수 | 계정에서 제공되지 않으면 `미제공`. 좋아요를 클릭으로 대체하지 않음 |
| 게임에서 시작·완료가 늘었나 | 기존 `match_started`, `match_finished`와 관리자 완료 경기 집계 | 클라이언트 이벤트는 플레이어 관점, 중복·누락 가능. 실제 경기 수는 관리자 DB 집계 |
| 친구 대전이 가능한가 | 직접 진행한 소규모 플레이의 완료 여부·입장 문제 | 테스트 참가자 경험을 일반 이용자 전체 통계로 표현하지 않음 |
| 다시 오고 싶어 하나 | 실제 재방문·재대전 관련 자발적 답변 | 현재 자료만으로 캠페인별 D1/D7 리텐션 계산 불가 |

같은 게시물을 실제 발행 시각부터 24시간·72시간 시점에 각각 기록한다. 표의 발행일이 바뀌면 관측 시각도 함께 바꾼다. 노출과 클릭이 모두 제공될 때만 `링크 클릭 수 ÷ 노출 수`를 참고치로 계산한다. 작은 표본에서는 한 게시물을 승자로 확정하지 말고 유사 소재로 재확인한다. 시간·언어·매체가 다르면 통제된 A/B 테스트라고 부르지 않는다.

현재 [통계 코드](../../apps/web/src/lib/analytics.ts)는 URL query/hash를 지운다. UTM을 붙인 것만으로 Vercel에서 캠페인별 유입·전환을 측정할 수 있다고 가정하지 않는다. 이번 초안은 일반 링크를 사용한다. 게시 시간과 게임 전체 수치를 비교하더라도 다른 유입이 섞인 **상관관계**이며 게시물의 기여 전환으로 보고하지 않는다. 새 추적 기능은 추가하지 않았다. 자세한 제한은 [통계 문서](../analytics.md).

YouTube는 2025-03-31부터 Shorts 시작·재생 반복을 조회수에 포함하고 별도로 `Engaged views`를 제공한다고 안내한다. 가능하면 Shorts끼리는 이 참여 지표도 같이 보고, X 조회수와 단순 비교하지 않는다. [공식 안내](https://support.google.com/youtube/answer/10059070?hl=en)

### 다음 행동을 고르는 기준

- 규칙 질문이 반복되면 V1의 원인·결과가 보이는 부분과 첫 문장을 먼저 바꾼다.
- 클릭 후 방 입장에서 막히면 노출을 늘리기보다 V2와 실제 동선을 점검한다.
- 상대를 못 만나면 친구 초대·정해진 공동 플레이 시간으로 모은다. 자동 매칭이 즉시 된다고 광고하지 않는다.
- 실제 완주 경험이 쌓이고 운영자가 답변할 여력이 있을 때 소규모 게임 채널 후보를 고른다. 이번에는 DM·메일·댓글 영업을 보내지 않았다.
- 유료 광고·경품은 첫판 경험과 계측이 확인된 뒤 별도 예산으로 판단한다.

## 게시 직전 확인

1. 선택한 글·실제 첨부 파일·목적지 링크를 한 묶음으로 확인한다. X 작성창의 글자 수와 링크 미리보기도 확인한다.
2. 화면 속 규칙, 게스트 가능 범위, 1024 승리 조건이 현재 운영과 일치해야 한다.
3. 남의 닉네임·개인 메시지·운영 화면·진행 중인 방 코드를 노출하지 않는다.
4. 커뮤니티 규칙과 작성자 자격, 필요한 AI 사용 공개를 확인한다. 이용자가 쓴 후기처럼 꾸미지 않는다.
5. 예약·게시·광고·외부 연락은 사용자의 실행 지시가 있는 범위에서 진행한다.

## 이번 준비의 검수

카피의 주요 사실을 저장소와 대조했고, 운영 게스트 메뉴를 읽어 동선 문구를 맞췄다. 벤치마크의 관찰과 적용 가설을 구분했다. 존재하지 않는 출시일·성과·사용자 후기·행사 일정은 넣지 않았다. 별도 검수에서 지적한 공격 조건의 모호한 표현과 72시간 관측 날짜를 수정했다. 로컬 문서 링크, X 게시문 14개의 보수적인 글자 수 계산, CSV의 24·72시간 관측 행을 검사했다. 문서 작업이므로 앱 테스트·빌드·의존성 설치는 하지 않았다. 촬영과 실제 운영 한 판 완료는 남아 있다.
