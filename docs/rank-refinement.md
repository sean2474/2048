# Elo 기반 랭크 정리 — 2026-10-17

> 랭크 개편의 설계·검증 이력이다. 현재 경기 규칙은 [랭크 시즌](ranked-seasons.md), 구현된 영구 수집품은 [랭크 보상](rank-cosmetics.md)을 따른다. 시즌 종료 순위 보상은 별도 미구현 항목이다.

사용자가 생각한 체스식 Elo를 중심으로 정리하고 **구현에 반영한 설계 기록**이다. 승급전 제거, 생애 Elo 유지, 최초 평가와 시즌 참가 10경기, 양쪽 대기시간·최대 300점 매칭을 적용했다. 현재 규칙과 최종 검증은 [Elo·최초 평가·랭크 시즌](ranked-seasons.md)을 따른다. 아래 설계 검토와 앞선 버그 수정 기록은 결정 배경으로 보존한다.

## 기준: 점수 하나로 실력·매칭·현재 티어를 연결

현재 구현도 초기 1200, K32인 Elo다. 다른 레이팅 알고리즘으로 교체하기보다 승급전과 시즌 초기화 규칙을 단순화한다. 높은 점수의 상대를 이기면 더 많이 오르고, 낮은 점수의 상대에게 지면 더 많이 떨어진다. 경기 점수·최대 타일·연승·출석은 Elo에 별도 가산하지 않는다.

체스 Elo의 기대 성적 대비 결과를 반영하는 원리를 참고한다. FIDE는 실제로 선수 조건에 따라 K를 다르게 적용하고 별도 초기 점수 규칙을 둔다. 아래의 1200·K32·10경기·티어는 **우리 게임의 초기 설계값**이며 FIDE 규정의 복제가 아니다. [FIDE 레이팅 규정 8.2–8.3](https://handbook.fide.com/chapter/B022024)

| 항목 | 제안 |
| --- | --- |
| 실력 점수 | 공개 Elo 하나를 매칭과 순위에 사용. 별도 LP나 숨겨진 실력 점수를 추가하지 않음 |
| 점수 계산 | 기존 K32 유지. 한쪽 델타를 반올림하고 상대는 반대 부호로 적용해 합계 변화 0 유지 |
| 신규 이용자 | 1200에서 시작. 최초 10경기는 점수와 ‘평가 중 N/10’을 표시하고 공식 티어는 보류. 무승부도 유효 경기로 계산 |
| 티어 | 기존 점수 구간 유지. 평가 완료 뒤 매 결과의 Elo로 즉시 승급·강등. 승급전·강등 보호 없음 |
| 시즌 | Elo와 이미 평가된 현재 티어는 유지. 시즌 전적·순위표 참가 경기 수·시즌 최고 기록을 새로 시작 |
| 시즌 참가 | 해당 시즌 랭크 10경기부터 순위표·시즌 보상 대상. 기존 이용자의 실력을 다시 초기화하는 배치가 아님 |
| 보상 | 기존 평가 완료자는 첫 실제 시즌 경기부터 최고 티어를 기록하고, 시즌 10경기를 채우면 보상 자격 부여. 신규 이용자는 공식 티어를 얻는 10번째 경기부터 기록. 이후 강등해도 최고 기록과 지급된 꾸미기 보상 유지. 보상 종류·수량은 별도 설계 |
| 매칭 | 가까운 Elo 우선. 각자의 대기시간으로 허용 범위를 계산하고 두 범위를 모두 만족할 때 연결 |

티어 구간은 브론즈 `<1000`, 실버 `1000–1199`, 골드 `1200–1399`, 플래티넘 `1400–1599`, 다이아몬드 `1600–1799`, 마스터 `1800 이상`이다. 최고 시즌 기록은 현재 실력 티어와 별도로 표시한다. 시즌 시작 때 물려받은 점수만으로 최고 기록이나 보상 자격을 부여하지 않는다.

10경기는 공식 표시·참가의 최소 요건이지, 정확한 실력 산정을 보장하는 숫자가 아니다. 고정 K32라 초기 실력이 1200과 크게 다른 사람의 수렴은 느릴 수 있다. 신규 이용자 K를 높이는 안은 실제 초기 승률·점수 추이를 본 뒤 검토한다. 개인별 K를 달리하면 양쪽 점수 증감이 같지 않을 수 있으므로 이를 단순한 숫자 변경으로 취급하지 않는다.

## 점수 변화 예시

현재 구현의 계산식은 `기대 성적 = 1 / (1 + 10^((상대 Elo - 내 Elo) / 400))`, `변화량 = round(32 × (결과 - 기대 성적))`이다. 결과는 승리 1, 무승부 0.5, 패배 0이다. 기대 성적은 무승부를 포함하므로 단순 승리 확률과 같다고 설명하지 않는다.

내 점수가 1200일 때:

| 상대 Elo | 승리 | 무승부 | 패배 |
| --- | ---: | ---: | ---: |
| 1000 | +8 | −8 | −24 |
| 1200 | +16 | 0 | −16 |
| 1400 | +24 | +8 | −8 |

표는 기존 계산식으로 검산했다. 서버 반올림은 PostgreSQL 규칙을 유지하고 한쪽 델타만 계산한다. 클라이언트는 저장된 증감을 표시한다. 강한 상대와 비기면 점수가 오르고, 약한 상대와 비기면 내려갈 수 있으며 티어 경계를 넘으면 무승부에도 티어가 바뀐다.

## 매칭과 시즌 경계

- 매칭의 수치 초안은 각자 `±150`에서 10초마다 50씩 확대하고 `±300`에서 멈춘다. 두 사람 중 짧은 대기시간이 허용하는 범위까지로 제한한다. 오래 기다린 한 사람이 새 참가자의 허용 범위를 넓히지 않는다. 적합한 상대가 없으면 대기를 계속하며 점수 차이를 무제한으로 늘리지 않는다. 상한은 동접·대기시간을 측정한 뒤 조정할 값이다.
- 시즌 변경 때 Elo를 1200 방향으로 압축하지 않는다. 전적과 참가 자격만 시즌 단위로 나눠 상위·하위 이용자의 실력 정보를 유지한다. 초기 티어 구간도 이용자 분포를 보며 검토하되 백분위로 자동 이동시키지 않는다.
- 생애 Elo로 변경하면 현재의 ‘이전 시즌의 늦은 결과는 현재 Elo에 영향 없음’ 규칙도 바꿔야 한다. 유효한 랭크 결과는 저장 트랜잭션 순서로 생애 Elo에 정확히 한 번 반영하고, 시즌 전적은 경기 시작 시각의 시즌에만 반영한다. 종료 시즌 점수를 현재 Elo에 덮어쓰거나 같은 델타를 재전송 때 다시 더하지 않는다.
- 시즌 소속은 기존처럼 서버의 방 생성 시각으로 정한다. 이전 시즌 경기의 지연 저장은 새 시즌 참가 경기 수를 올리지 않는다. 시즌 최종 순위·보상은 종료 전에 시작한 경기와 결과 저장 재시도가 정리된 뒤 확정해야 한다. 종료 시즌 순위는 각 참가자의 해당 시즌 마지막 유효 경기 `rating_after`를 사용하며, 새 시즌 결과가 반영된 현재 생애 Elo로 과거 순위를 덮어쓰지 않는다. 현재 구현에는 보상 확정 절차가 없으므로 점수 초기화 식만 제거하고 끝낼 수 없다.

## 구현 영향 범위와 회귀 조건

Elo 산식을 재사용하면서 DB의 권위 있는 Elo 저장 위치와 시즌 집계, 5경기→10경기 요건, 승급전 제거, 최고 시즌 기록·참가 자격을 함께 변경했다. 기존 점수는 보존하고 새 점수 기준으로 현재 티어를 계산하되 과거 경기·시즌 스냅샷은 덮어쓰지 않는다. 기존 참가자의 시즌 자격은 해당 시즌의 저장된 유효 경기 수로 이어받는다.

공유 스키마, 서버 매칭, DB 결과 저장·시즌 전환, 홈·순위표·대전 소개·결과·기록·게임 방법, 관리자 시즌 안내, 번역, 단위/DB/브라우저 fixture가 영향 범위다. README와 [현재 규칙 문서](ranked-seasons.md)도 현재 구현에 맞췄다.

필수 회귀 조건은 같은 점수·큰 점수 차·무승부 계산, 양측 델타 합계 0, 9→10번째 경기, 티어 경계 직전·정확히 도달·강등, 최고 기록 유지, 서로 다른 대기시간과 매칭 상한, 결과 중복·저장 실패·재시도, 시즌 전환 중 경기와 과거 시즌 지연 저장이다. 서버가 무효 처리한 경기는 점수·참가 경기 수·보상을 바꾸지 않는다.

관련 경로: `packages/schema/ranking.ts`, `apps/socket/src/matchmaking.ts`, `supabase/migrations/20261017020000_rank_seasons.sql`, `apps/web/src/components/widget/rank-progress.tsx`, `match-result.tsx`.

## 앞선 작업에서 수정한 모순 — 기존 승급전 구현

- 승급 후 Elo가 새 티어 하한보다 낮으면 다음 판을 이겨도 강등되던 경로를 수정했다. 승리와 무승부에서는 획득 티어를 유지하고, 패배 때 하한 미달을 검사한다. 승급전에서 두 번째 패배로 실패하는 경우의 강등 검사는 유지한다.
- 경기 결과에 서버가 저장한 `rating_delta`를 명시하도록 했다. 아직 저장되지 않은 값을 승패만으로 계산하지 않는다.
- 기록 저장 불가 상태에서 ‘저장 후 티어가 갱신된다’는 안내가 나오지 않도록 했다.
- 게임 방법의 이전 ‘Elo로 바로 티어 결정’ 설명을 현재 배치·승급전 규칙에 맞췄다.

재현 사례: Gold 1399 → 승리 1402(승급전 시작) → 패배 1373 → 승리 1377 → 승리 1381(Platinum 승급) → 승리 1385. 마지막 경기에서 Gold로 떨어지던 것을 Platinum 유지로 바꾼다. 이후 하한 미달에서 무승부도 유지, 패배하면 강등한다.

당시 시즌 마이그레이션은 운영 DB에 적용되지 않은 파일을 수정했다. 운영 DB 적용·배포·운영 계정 점수 보정은 실행하지 않았다.

## 앞선 구현의 검증 결과 — 위 설계안의 통과 기록이 아님

- 전체 단위·DB 테스트 138개와 번역 테스트 2개 통과. 새 SQL 회귀는 기존 코드에서 실패를 확인한 뒤 수정했다.
- 랭크 브라우저 3개 통과: 대시보드·시즌 기록, 점수 증감(+/−/0/누락), 저장 대기→완료, 조회 오류→재시도, 저장 불가 안내와 조회 차단. 데스크톱 및375px 화면 겹침 없음.
- 타입 검사·웹/어드민 ESLint 통과. 임시 복사본에서 웹 프로덕션 빌드 통과.
- 코드·React·TypeScript 독립 검토에서 해결되지 않은 결함 없음.
- 전체 검사에서 기존 공격 테스트가 무작위 시작 타일 위치 때문에 의도한 이동을 무효 이동으로 만드는 문제가 드러났다. 테스트만 왼쪽 타일을 명시해 유효 이동을 보장했다. 실제 게임 판정은 변경하지 않았다.

매칭 상한과 배치 조정은 실제 동접·대기시간·승률 분포로 검증하지 않았다. 운영 DB 적용·배포도 실행하지 않았다.
