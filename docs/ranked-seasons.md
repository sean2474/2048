# Elo·최초 평가·랭크 시즌

## 현재 규칙

- 랭크전은 서로 다른 로그인 계정의 Elo를 갱신한다. 일반전·친구 대전은 Elo·평가·시즌 순위에 영향을 주지 않는다.
- 초기 Elo는 **1200**, K는 **32**다. 기대 성적은 `1 / (1 + 10^((상대 Elo - 내 Elo) / 400))`, 변화량은 `round(32 × (결과 - 기대 성적))`이다. 결과는 승리 1, 무승부 0.5, 패배 0이다. PostgreSQL 반올림으로 한쪽 델타를 계산하고 상대에게 반대 부호를 적용한다.
- 최초 랭크 **10경기** 동안 점수와 평가 진행도를 공개하고 공식 티어를 보류한다. 무승부도 1경기로 센다. 시즌이 바뀌어도 평가 진행도는 유지되며 10에서 멈춘다. 10경기는 표시 기준이며 정확한 실력 추정의 보장은 아니다.
- 평가 완료 뒤 현재 Elo로 **즉시 승급·강등**한다. 승급전·별도 LP·강등 보호는 없다. 강한 상대와 비겨 승급하거나 약한 상대와 비겨 강등될 수 있다.
- 브론즈 `<1000`, 실버 `1000–1199`, 골드 `1200–1399`, 플래티넘 `1400–1599`, 다이아몬드 `1600–1799`, 마스터 `1800 이상`이다.
- **현재 Elo와 티어는 시즌이 바뀌어도 유지**된다. 각 시즌의 승·패·무승부, 최고 점수·타일, 시즌 최고 Elo는 새로 시작한다. 해당 시즌 랭크 **10경기부터 순위표**에 등재된다. 기존 이용자의 재배치가 아니다.
- `peak_rating`은 공식 티어가 있는 실제 시즌 경기 결과 중 최고 Elo다. 평가 완료자는 첫 시즌 경기부터, 신규 이용자는 최초 10번째 경기부터 기록한다. 시즌 시작 시 물려받은 점수만으로 최고 기록을 만들지 않는다. 이후 강등해도 최고 기록은 유지한다.
- 시즌 보상 자격은 해당 시즌 10경기와 최고 기록으로 판단할 수 있다. 이 변경은 최고 기록과 참가 요건을 구현하며 **보상 품목·지급·확정 기능은 포함하지 않는다**. 출석 등 기존 업적 보상은 별도 규칙대로 동작한다.

## 매칭

서로 가까운 Elo를 우선한다. 각자의 대기시간에 따라 허용 격차가 ±150에서 10초마다 50씩 확대되며 최대 ±300이다. 두 사람 모두의 범위를 만족해야 하므로 짧은 대기시간을 기준으로 판단한다. 적합한 상대가 없으면 대기를 계속하며 상한을 자동 해제하지 않는다. 동접이 적거나 최상위·최하위에서는 대기가 길어질 수 있다.

대기열에서 상대를 고르기 전에 최신 Elo를 다시 읽는다. 조회 중 취소·접속 종료·서버 종료된 요청을 되살리지 않는다. 일반전과 랭크전 매칭 작업을 분리해 랭크 조회 지연이 일반전 매칭을 막지 않는다. 결과 저장 대기 중인 계정은 다른 세션에서도 새 랭크전에 들어가지 못하며, 저장 재시도 성공 후 재참가한다.

## 시즌 전환과 지연 결과

관리자는 `/seasons`에서 현재 시즌·새 시즌 이름·사유를 확인하고 수동으로 전환한다. 현재 시즌 ID를 비교하고 전환과 결과 저장에 공통 트랜잭션 advisory lock을 사용한다. 중복 클릭·오래된 요청은 시즌을 두 번 만들지 않는다. 전환 시각은 잠근 현재 시즌 시작보다 최소 1마이크로초 뒤로 보장해 연속 전환이나 시계 역행에도 구간이 겹치지 않는다. 실행한 관리자·사유는 관리자 감사 조회에만 공개한다.

경기 소속 시즌은 **서버에서 방을 만든 시각 `startedAt`**으로 고정한다. 시즌 구간은 시작 포함·종료 제외다. 시즌 전환을 가로지른 경기와 저장 실패 후 재시도는 시작한 시즌에 기록한다.

유효한 랭크 결과는 저장 트랜잭션 순서로 생애 Elo에 정확히 한 번 반영한다. **이전 시즌 결과가 늦게 저장돼도 현재 Elo·티어·최초 평가 진행도는 갱신**된다. 전적·시즌 최고 기록은 해당 경기 시즌에만 추가하고, 새 시즌 경기 수·최고 기록은 변경하지 않는다. 경기 UUID 중복 요청은 어느 값도 다시 변경하지 않는다.

종료 시즌의 순위 점수는 해당 시즌 마지막으로 저장된 유효 경기의 `rating_after`다. 새 시즌 경기를 치러도 과거 순위·경기 스냅샷은 덮어쓰지 않는다. 새 시즌 참가자가 아직 없어도 늦은 결과는 생애 점수로 보존한다. 현재 시즌 순위는 생애 점수를 사용하므로 과거 시즌 결과의 지연 저장에 따라 바뀔 수 있다.

시즌 구간 종료는 최종 보상 확정과 다르다. 종료 전 시작한 경기와 저장 재시도가 남아 있으면 과거 시즌 순위도 갱신될 수 있다. 향후 보상 지급 기능은 이 결과들이 정리된 후 확정해야 한다.

`season_ratings.rating`은 시즌 경기 스냅샷이므로 지연 결과가 있으면 현재 Elo와 다를 수 있다. 현재 순위표는 `player_ratings`, 종료 시즌 순위표는 `season_ratings`에서 `games_played >= 10`으로 조회한다. 평가 진행도를 순위표 참가 요건으로 대신 사용하지 않는다.

공개 `record_match`의 통계 검증·권한, 기존 outbox와 계정 잠금·UUID 중복 방지를 재사용한다. 랭크 결과와 시즌 전환은 현재 규모에서 직렬화된다. 사용자 이름 변경은 현재 시즌만 갱신하고 종료 시즌 이름은 당시 스냅샷으로 남긴다. 계정 삭제는 해당 계정의 시즌 순위 행을 삭제하고 경기 참여 기록은 기존 정책대로 익명화한다.

## 기존 데이터 이전과 배포

이 시즌 마이그레이션은 아직 운영에 적용하지 않은 미출시 파일이다. 이번 변경은 해당 파일을 최종 규칙으로 수정했다. 이미 이전 버전을 적용한 DB가 있다면 동일 파일을 재실행하지 말고 별도의 전진 마이그레이션을 준비해야 한다.

1. DB 백업 후 미적용 마이그레이션을 순서대로 **앱 배포보다 먼저** 적용한다. 첫 시즌은 기존 Elo·전적을 보존한다. 기존 유효 랭크 경기 수에서 최초 평가를 이어받으며, 10회 이상이면 현재 Elo의 공식 티어를 부여한다.
2. 기존 명시적 랭크 경기만 첫 시즌에 연결한다. `legacy` 경기와 과거 경기의 당시 표시 티어는 보존한다. 초기 시즌 하한 `1970-01-01`은 이전 outbox를 수용하는 소급 구간으로 서비스 출시일을 뜻하지 않는다.
3. 기존 최고 Elo는 최초 평가 이후의 기록과 현재 점수를 이용해 초기화한다. 기존 점수나 전적을 1200·0으로 덮어쓰지 않는다.
4. 소켓·웹·관리자 앱을 함께 배포한다. RPC 인자와 outbox 형식은 유지한다. 새 앱은 `peak_rating`과 새 평가 계약을 사용하므로 DB 적용 없이 먼저 배포하지 않는다.
5. 현재 시즌·평가·순위표 참가 조건·결과 저장을 확인한다. 시즌 종료는 별도 운영 작업이다.

자동 다운 마이그레이션은 제공하지 않는다. 실제 시즌 기록을 쌓은 뒤 테이블을 제거하거나 예전 시즌별 점수 계산으로 되돌리면 정합성이 깨진다. 되돌릴 때도 기록을 보존한 전진 마이그레이션이나 검증한 백업 복구가 필요하다.
