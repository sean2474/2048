# 같은 상대와 재대결

경기 결과의 **재대결** 버튼으로 방금 플레이한 상대에게 신청한다. 상대가 **재대결 수락**을 누르거나 양쪽이 재대결을 신청하면 새 보드로 바로 이동한다. 일반전·랭크전·친구전 모두 기존 모드를 유지하며, 친구전은 새 방 코드를 공유하지 않아도 된다.

- 경기 종료 후 60초 안에 서로 동의해야 한다. 한쪽의 신청만으로 시작하지 않는다.
- 신청자는 취소할 수 있고 상대는 거절할 수 있다. 취소·거절·만료 후에는 다른 상대 찾기 또는 새 친구방 만들기를 사용한다.
- 결과 창에서 마지막 보드 보기로 돌아가도 재대결 상태와 버튼을 유지한다.
- 어느 한쪽이 페이지를 떠나거나 연결이 끊기면 신청을 종료한다. 재접속이나 새로고침으로 이전 신청을 복원하지 않는다.
- 새 매칭·친구 방·솔로로 이동하거나 서버가 배포 대기 상태로 들어가면 이전 재대결을 시작하지 않는다.
- 랭크전은 이전 결과 저장이 완료된 뒤 신청할 수 있다. 양쪽 동의 후 정지 여부·최신 레이팅·저장 대기 결과·다른 기기의 참가 상태를 다시 확인한다. 새 경기의 Elo와 결과 저장 규칙은 기존 랭크전과 같다.

서버는 종료된 경기의 참가 세션만 재대결에 참여시킨다. 클라이언트는 상대나 모드를 지정할 수 없으며, 중복 수락과 비동기 계정 검사 도중의 취소·이탈로 추가 경기가 만들어지지 않는다. 이전 보드와 점수는 보존하지 않고 새 경기 ID·보드·능력 충전으로 시작한다.

## 검증

- `apps/socket/tests/multiplayer.test.ts`: 양쪽 동의, 중복 수락, 취소·거절·이탈, 외부 세션 차단, 친구전 모드 유지, 랭크 저장 대기와 최신 점수, 다른 매칭으로 이동, 계정 검사 중 취소·이탈·배포 대기·정지·다른 기기 참가.
- `apps/socket/tests/rematch.test.ts`: 요청 형식, 60초 제한과 같은 만료 처리, 늦은 수락 차단. 만료 단위 검사는 짧은 테스트 제한 시간을 주입한다.
- `apps/web/tests/rematch.browser.mjs`: 로컬 테스트 서버의 두 게스트가 두 번 연속 재대결하고, 마지막 보드에서 수락하며, 취소·거절·다른 상대 찾기·메뉴 이동을 수행한다. 한국어 화면의 키보드 수락과 375·768·1440px 배치를 확인한다.
- 캡처: `docs/rematch/request-375.png`, `request-768.png`, `request-1440.png`.

브라우저 테스트는 저장소 의존성을 바꾸지 않는 별도 Playwright 런타임을 `NODE_PATH`로 제공해 실행할 수 있다. 자체 임시 웹·소켓·API 서버를 사용하며 운영 계정이나 DB를 사용하지 않는다.

2026-10-22 기능 브랜치 검증: 전체 자동 테스트 320개, 재대결 브라우저 시나리오 1개, 전체 타입 검사·린트·웹/관리자 빌드 통과. 재대결 집중 테스트 14개는 전체 테스트에 포함되며, 해당 실행에서 `apps/socket/src/rematch.ts`의 줄 커버리지는 96.41%였다. 화면 캡처는 배치 확인 자료이며 이전 기준 이미지와의 자동 시각 비교나 실제 터치 기기 검증은 아니다. 빌드는 테스트 서버가 모두 종료된 상태에서 별도로 실행한다.

DB 마이그레이션은 필요 없다. 배포 시 [배포 가이드](deployment.md)에 따라 소켓 서버와 웹을 함께 반영한다. 기능 브랜치 검증은 운영 배포를 뜻하지 않는다.
