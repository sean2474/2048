# 설정 저장과 계정 관리

`/settings`는 키 바인딩, 사용자 지정 단축키 켜기/끄기, 한국어·영어, 닉네임, 음소거·음량·미리듣기, 로그아웃, 계정 삭제를 제공한다. 아이콘·스킨 선택은 `/loadout`, 능력 선택은 `/find-match`의 모달, 학습은 `/tutorial`과 `/how-to-play`로 연결한다.

## 저장 위치와 충돌 우선순위

| 상황 | 적용할 설정 |
| --- | --- |
| 비로그인 | 언어·키 설정은 게스트 쿠키. 아이콘·스킨·능력은 게스트 전용·클래식·X 1개 제거 기본 능력으로 고정 |
| 로그인, 계정 설정 있음 | DB 계정 설정 우선. 브라우저 설정으로 자동 덮어쓰지 않음 |
| 로그인, 계정 설정 없음 | 게스트 언어·키 설정과 기본 장비값을 최초 1회 복사. 동시에 다른 기기가 만들었으면 먼저 생성된 DB 설정 사용 |
| 로그아웃 | 로그인 전에 사용하던 게스트 쿠키 복원. 계정 설정을 게스트 설정에 복사하지 않음 |
| 같은 계정의 다른 기기에서 서로 다른 항목 변경 | 변경한 DB 컬럼만 업데이트하여 다른 항목을 보존 |
| 같은 항목을 여러 기기에서 변경 | 서버가 마지막으로 수락한 값 사용 |
| DB 조회/저장 실패 | 오류와 재시도 제공. 실패한 변경을 저장 완료로 표시하거나 게스트 값으로 DB를 덮어쓰지 않음 |

저장 항목은 `locale`, `keybindings`, `customShortcuts`, `skinId`, `iconId`, `abilityId`이다. 쿠키는 게임 환경만 담으며 개인정보·잔액·소유권·인증 근거로 쓰지 않는다. SSR용 `duo.locale`은 현재 적용 언어의 표시용 캐시이다. 계정별 설정은 RLS로 본인만 조회·삽입·수정 가능하며, 입력값과 키 중복은 브라우저와 DB에서 검증한다.

서버가 확인한 계정·설정은 provider의 초기값으로 전달하며 동일 요청 안의 조회를 공유한다. 브라우저는 입력·저장·실패 재시도를 담당한다. 서버 조회 실패는 설정이 없는 계정으로 취급하지 않고 기존 클라이언트 복구 흐름으로 처리한다. [렌더링 경계](page-performance-boundaries.md)를 참고한다.

## 소리 저장

음소거와 음량은 `duo.audio` localStorage에 저장하며 계정 DB 설정과 별개다. 같은 브라우저의 다른 탭에도 반영한다. 저장소를 사용할 수 없으면 현재 방문 동안만 적용하고, 미리듣기는 사용자가 버튼을 눌렀을 때 재생한다. 브라우저 자동 재생 제한에 따라 첫 사용자 조작 후 오디오를 활성화한다.

## 첫 접속 언어와 직접 선택

저장된 설정이 없는 첫 접속에는 Vercel의 `x-vercel-ip-country`가 `KR`이면 한국어, 그 외 국가는 영어를 적용한다. 국가가 없거나 알 수 없으면 `Accept-Language`에서 지원하는 한국어·영어 중 우선순위가 가장 높은 언어를 사용하고, 둘 다 없으면 영어를 사용한다. [Vercel 요청 헤더 문서](https://vercel.com/docs/headers/request-headers)를 기준으로 하며 별도 위치 권한이나 외부 IP 조회는 요청하지 않는다.

계정 DB → 게스트 설정 쿠키 → 기존 언어 쿠키 → 자동 감지 순으로 언어를 결정한다. 기존 언어 쿠키는 게스트 설정 쿠키가 아직 없는 이전 버전에만 적용한다. 자동으로 정한 첫 언어도 게스트 설정에 저장하여 이후 방문이나 위치 변경으로 갑자기 바뀌지 않게 한다. 설정의 한국어·English 선택 카드에서 바꾼 값은 로그인 시 DB, 비로그인 시 쿠키에 저장한다. 키보드 Tab·방향키로도 선택할 수 있다. 공통 헤더에는 언어 선택을 표시하지 않는다.

서버가 선택한 게스트 언어를 클라이언트에 별도로 전달하므로 첫 화면과 클라이언트 초기화 이후의 언어가 일치하고, 계정의 언어가 게스트 기본 언어를 덮어쓰지 않는다.

방향키는 고정이고 추가 이동·특수 능력 키는 문자/숫자/스페이스바로 바꿀 수 있다. 기본값은 이동 W/A/S/D, 특수 능력 스페이스바다. 키 설정에서 5개 동작의 중복 키를 거절하며 ‘기본값으로’ 버튼으로 초기화한다. 일반 공격은 자동이라 키 설정이 없다. 내 보드 아래 능력 버튼에 현재 키와 충전율을 표시한다. 사용자 지정 단축키를 끄면 키 표시·키보드 발동을 끄고 방향키와 화면 버튼은 유지한다. 물리 키 코드를 저장해 한글 입력 상태에서도 같은 위치를 사용한다. 설정창에서는 게임 입력을 멈추며 Escape 취소와 Tab 이동을 지원한다.

기존 6·7개 키 설정은 읽을 때 공격 키를 제거하고 이동키와 사용자 지정 능력 키를 보존한다. 이전 기본 능력 키 3 또는 능력 키가 없는 설정은 스페이스바부터 첫 빈 키를 선택한다. 현재 5개 형식에서 사용자가 지정한 3번은 유지한다. 조회만으로 계정 행을 덮어쓰지 않으며 다음 저장 때 5개 키를 기록한다. `20261017060000_manual_ability_key.sql`은 기존 형식과 새 5개 형식을 허용하고 새 행 기본값을 1로 변경한다. 웹 배포 전에 적용한다.

사용자 지정 단축키 켜기/끄기는 대전 중 키 설정창에서 변경한다. 키와 함께 저장하며 취소하면 적용하지 않는다. 저장 실패 시 기존 설정과 연결을 유지한다.

능력 키는 충전 부족·효과 적용 중·재접속 일시정지·설정창·기권 확인창·입력 필드·메뉴에서는 발동하지 않는다. 길게 누른 반복 입력과 Shift/Ctrl/Alt/Command 조합도 무시한다. 튜토리얼 마지막 단계에서도 같은 저장 키로 능력을 사용할 수 있다.

이동은 방향키와 사용자 지정 키가 같은 입력 처리를 사용한다. 누르는 즉시 한 번 이동하고 200ms 이상 누르면 70ms 간격으로 반복한다. 서로 다른 방향을 빠르게 누른 입력도 전송하며, 키를 놓거나 창·탭·입력 필드로 초점을 옮기거나 대전이 잠기면 반복을 중단한다. OS의 키 반복 속도 설정에 의존하지 않는다.

회원가입 요청에 성공하면 입력값을 지우고 완료 안내로 폼을 교체한다. 이메일 확인이 필요한 경우 확인 후 로그인하도록 안내하며, 즉시 로그인된 경우 게임으로 이동하는 버튼을 표시한다. 실패했을 때는 입력값을 유지해 수정·재시도할 수 있다.

실전 방향패드는 700px 미만 화면에서만 표시한다. 모바일 버튼당 최소 44×44px이며 375px 이상 화면에서는 52×52px, 간격은 6px이다. 한 번 탭하면 한 번 이동하고 길게 눌러도 자동 반복하지 않는다. `touch-action: manipulation`으로 더블 탭 확대를 막으며 보드 스와이프도 지원한다. 튜토리얼에서는 화면 크기와 관계없이 방향패드를 유지한다.

256·512 병합은 서버에서 X·하드블록을 자동 발사한다. 양쪽 공격권 슬롯과 수동 공격 버튼은 표시하지 않는다. 내 능력은 내 보드 아래에서 수동 사용하며 상대 능력도 아이콘·이름·충전율로 확인한다. 공격 예고는 짧은 보드 이펙트로 보여주며 하단 도착 예정 개수는 표시하지 않는다. 두 플레이어 이름 왼쪽에 서버가 확인한 프로필 아이콘을, 상단 대전 상태 옆에 일반전·경쟁전·친구전 아이콘을 표시한다. 작은 화면은 스크롤을 허용해 보드와 조작부가 겹치지 않게 한다. 대시보드의 ‘튜토리얼 하기’에서 자동 공격과 능력 사용을 연습한다.

2026-10-16 검증: 언어 감지·설정 회귀 테스트 11개와 웹 타입 검사·린트 통과. 격리 브라우저에서 국가별 첫 렌더링과 초기화 후 언어 일치, 직접 선택·새로고침·위치 변경 시 유지, 키보드 선택, 저장 오류, 튜토리얼의 X·하드 충전→버튼 발사→소진 비활성화를 확인했다. 순위·보관함 브라우저 테스트도 언어 변경 경로를 설정 페이지로 바꿔 통과했다. 별도 로컬 Socket.IO 테스트 서버로 대전 UI의 공격 메시지·개수 갱신·일시정지 잠금과 320×740, 375×660, 375×812, 768×1024, 1440×900 화면의 가로·세로 넘침 없음을 확인했다. 이 UI 검증은 실제 사용자나 운영 경기 데이터를 만들지 않는다. 실제 휴대폰의 조작감과 Vercel 배포의 국가 헤더는 아직 실측하지 않았다.

## 닉네임과 계정 삭제

닉네임은 앞뒤 공백을 제거한 1–32자이다. `players.name`이 기준이며 헤더·다음 대전·순위에 반영한다. 완료 경기의 닉네임은 당시 기록으로 남는다.

계정 삭제는 현재 이메일을 직접 입력하고 최종 버튼을 눌러야 실행한다. 기존 대전 서버의 `POST /account/delete`가 Bearer 토큰을 검증하고 본인 계정만 삭제한다. 관리자 계정은 먼저 별도로 권한을 해제해야 한다. 진행 중 멀티플레이나 미저장 결과·솔로 저장 작업이 있으면 삭제를 거절하고, 처리 중에는 새 매칭을 막는다. 저장을 마친 솔로가 진행 중이라는 이유만으로 삭제를 막지는 않는다. 세션을 전역 해제한 뒤 Supabase Admin API로 계정을 삭제한다. 비밀 키는 소켓 서버에만 둔다.

삭제 범위: 로그인 계정, 프로필, 코인 지갑, 계정 설정, 랭크·개인 통계, 구매·출석·업적·일일 퀘스트 기록, 솔로 기록·진행상황, 친구 관계와 해당 계정이 보내거나 받은 개인 메시지. 상대방의 경기 기록은 유지하되 삭제된 참가자의 이름을 `Deleted player`로 익명화하고 계정 참조를 제거한다. 운영 감사 기록은 유지한다. 브라우저의 별도 게스트 설정은 계정 데이터가 아니므로 남는다.

현재 게임 서버가 단일 인스턴스로 매칭·진행 상태를 소유하는 구조에 맞춘다. 여러 소켓 인스턴스로 확장할 때는 활성 경기와 삭제 잠금을 공유 저장소에서 조정해야 한다.


## 2026-10-22 스페이스바 기본 키

새 기본 능력 키는 `Space`이다. 게임 중 스페이스바를 길게 눌러도 능력은 한 번만 실행하고 페이지 스크롤을 막는다. 입력 필드·모달·메뉴에서는 게임 입력을 받지 않으며, 버튼·링크 등 포커스된 조작 요소에서는 스페이스바의 원래 동작을 유지한다.

기존 5개 키의 기본 능력 `Digit1`은 계정 데이터 전환과 구형 게스트 쿠키 읽기에서 `Space`로 변경한다. 다른 능력 키와 이동키·언어·단축키 활성화 설정은 유지한다. 게스트 쿠키는 버전 2 형식으로 저장하므로 변경 이후 사용자가 다시 지정한 `Digit1`도 유지한다. 계정은 일회성 데이터 전환 후 선택한 키를 그대로 저장한다. 이미 다른 동작에 `Space`를 지정했다면 덮어쓰지 않는다.

배포는 환경별로 다음 순서를 지킨다. 소켓 변경은 없다.

1. `20261022043632_space_keybindings.sql`로 DB에서 `Space` 저장을 허용한다. 기존 행과 기본값은 그대로 둔다.
2. 새 웹을 배포하고 스페이스바 입력·설정 저장을 검증한다.
3. `20261022043633_space_ability_default.sql`로 새 DB 기본값과 이전 기본 능력 키를 전환한다. 이 파일을 구형 웹보다 먼저 적용하지 않는다.

두 번째 파일은 웹 배포 후 적용하는 후속 데이터 전환이다. DB 변경을 한꺼번에 모두 적용하는 배포는 금지한다. 롤백이 필요하면 `Space`를 읽을 수 있는 웹 버전을 사용한다.

## 언어 동기화 브라우저 회귀 검사

`apps/web/tests/settings-locale-sync.browser.mjs`는 로컬 서버 fixture로 Chrome Android·WebKit iPhone 화면을 검사한다. 영어 → 한국어 → 새로고침 → 영어 흐름에서 서버 제목·설정 섹션, 클라이언트 라벨, 선택값, 두 언어 쿠키가 일치하는지 확인한다. 한국어 서버 응답 전달을 보류한 동안 영어를 선택한 경우에도 마지막 선택이 유지되는지 확인한다. 실제 계정·DB·운영 서버는 사용하지 않으며 테스트마다 개발 서버 포트와 빌드 출력을 분리한다.

먼저 저장소에서 `pnpm install --frozen-lockfile`을 실행한다. 테스트 실행 환경에는 Playwright 패키지, Google Chrome(`channel: "chrome"`), 설치한 Playwright 버전에 맞는 WebKit 브라우저가 필요하다. 외부 Playwright 런타임을 사용하는 경우 다음과 같이 실행한다. WebKit이 필요한 검사이므로 기존 Chrome 전용 성능 검사에 자동으로 포함하지 않는다.

```sh
NODE_PATH=/path/to/playwright/node_modules node --test apps/web/tests/settings-locale-sync.browser.mjs
```

Playwright가 저장소의 모듈 경로에서 이미 조회되면 `NODE_PATH`는 생략할 수 있다. 브라우저가 없으면 Playwright CLI의 `install chrome webkit`으로 설치한 뒤 실행한다. 휴대폰 화면·터치 에뮬레이션이며 실제 기기 검증을 대체하지 않는다.
