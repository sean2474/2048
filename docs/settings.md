# 설정 저장과 계정 관리

`/settings`는 키 바인딩, 사용자 지정 단축키 켜기/끄기, 한국어·영어, 닉네임, 로그아웃, 계정 삭제를 제공한다. 아이콘·스킨 선택은 `/loadout`, 능력 선택은 `/find-match`의 모달, 학습은 `/tutorial`과 `/how-to-play`로 연결한다.

## 저장 위치와 충돌 우선순위

| 상황 | 적용할 설정 |
| --- | --- |
| 비로그인 | 언어·키 설정은 게스트 쿠키. 아이콘·스킨·능력은 게스트 전용·클래식·X 1개 제거 기본 능력으로 고정 |
| 로그인, 계정 설정 있음 | DB 계정 설정 우선. 브라우저 설정으로 자동 덮어쓰지 않음 |
| 로그인, 계정 설정 없음 | 게스트 언어·키 설정과 기본 장비값을 최초 1회 복사. 동시에 다른 기기가 만들었으면 먼저 생성된 DB 설정 사용 |
| 로그아웃 | 로그인 전에 사용하던 게스트 쿠키 복원. 계정 설정을 게스트 설정에 복사하지 않음 |
| 같은 계정의 다른 기기에서 서로 다른 항목 변경 | 변경한 DB 컬럼만 업데이트하여 다른 항목을 보존 |
| 같은 항목을 여러 기기에서 변경 | 서버가 마지막으로 수락한 값 사용 |
| DB 조회/저장 실패 | 오류와 재시도 제공. 실패한 변경을 저장 완료로 표시하거나 게스트 값으로 DB를 덮어쓰지 않음 |

저장 항목은 `locale`, `keybindings`, `customShortcuts`, `skinId`, `iconId`, `abilityId`이다. 쿠키는 게임 환경만 담으며 개인정보·잔액·소유권·인증 근거로 쓰지 않는다. SSR용 `duo.locale`은 현재 적용 언어의 표시용 캐시이다. 계정별 설정은 RLS로 본인만 조회·삽입·수정 가능하며, 입력값과 키 중복은 브라우저와 DB에서 검증한다.

## 첫 접속 언어와 직접 선택

저장된 설정이 없는 첫 접속에는 Vercel의 `x-vercel-ip-country`가 `KR`이면 한국어, 그 외 국가는 영어를 적용한다. 국가가 없거나 알 수 없으면 `Accept-Language`에서 지원하는 한국어·영어 중 우선순위가 가장 높은 언어를 사용하고, 둘 다 없으면 영어를 사용한다. [Vercel 요청 헤더 문서](https://vercel.com/docs/headers/request-headers)를 기준으로 하며 별도 위치 권한이나 외부 IP 조회는 요청하지 않는다.

계정 DB → 게스트 설정 쿠키 → 기존 언어 쿠키 → 자동 감지 순으로 언어를 결정한다. 기존 언어 쿠키는 게스트 설정 쿠키가 아직 없는 이전 버전에만 적용한다. 자동으로 정한 첫 언어도 게스트 설정에 저장하여 이후 방문이나 위치 변경으로 갑자기 바뀌지 않게 한다. 설정의 한국어·English 선택 카드에서 바꾼 값은 로그인 시 DB, 비로그인 시 쿠키에 저장한다. 키보드 Tab·방향키로도 선택할 수 있다. 공통 헤더에는 언어 선택을 표시하지 않는다.

서버가 선택한 게스트 언어를 클라이언트에 별도로 전달하므로 첫 화면과 클라이언트 초기화 이후의 언어가 일치하고, 계정의 언어가 게스트 기본 언어를 덮어쓰지 않는다.

방향키는 고정이고 추가 이동·공격·특수 능력 키는 문자/숫자로 바꿀 수 있다. 기본값은 이동 W/A/S/D, X 공격 1, 하드 공격 2, 특수 능력 3이다. 키 설정에서 7개 동작의 중복 키를 거절하며, ‘기본값으로’ 버튼을 눌러 함께 초기화한다. 특수 능력 버튼은 현재 키를 표시하며 사용자 지정 단축키를 끄면 키 표시와 키보드 발동을 함께 끈다. 화면 버튼은 계속 사용할 수 있다. 물리 키 코드를 저장해 한글 입력 상태에서도 같은 위치의 키를 사용한다. 키 입력 설정창에서는 게임 입력을 멈추며 Escape 취소와 Tab 이동을 지원한다.

기존 6개 키만 저장된 계정·게스트 설정은 읽을 때 모든 기존 키를 보존하고 특수 능력에 3부터 시작하는 첫 빈 숫자 키(3·4·5·6·7·8·9·0·1·2 순)를 지정한다. 조회만으로 계정 행을 덮어쓰지 않으며 다음 키 설정 저장 시 7개 키를 기록한다. DB 마이그레이션 `20261016175755_ability_keybinding.sql`은 정확한 6개·7개 형식을 모두 허용하고 새 행 기본값만 변경해 구버전 클라이언트도 저장할 수 있다. 웹 배포 전에 이 마이그레이션을 적용해야 한다.

능력 키는 충전 부족·효과 적용 중·재접속 일시정지·설정창·기권 확인창·입력 필드·메뉴에서는 발동하지 않는다. 길게 누른 반복 입력과 Shift/Ctrl/Alt/Command 조합도 무시한다. 튜토리얼 마지막 단계에서도 같은 저장 키로 능력을 사용할 수 있다.

이동은 방향키와 사용자 지정 키가 같은 입력 처리를 사용한다. 누르는 즉시 한 번 이동하고 200ms 이상 누르면 70ms 간격으로 반복한다. 서로 다른 방향을 빠르게 누른 입력도 전송하며, 키를 놓거나 창·탭·입력 필드로 초점을 옮기거나 대전이 잠기면 반복을 중단한다. OS의 키 반복 속도 설정에 의존하지 않는다.

회원가입 요청에 성공하면 입력값을 지우고 완료 안내로 폼을 교체한다. 이메일 확인이 필요한 경우 확인 후 로그인하도록 안내하며, 즉시 로그인된 경우 게임으로 이동하는 버튼을 표시한다. 실패했을 때는 입력값을 유지해 수정·재시도할 수 있다.

모바일 대전과 튜토리얼의 하단 방향패드는 버튼당 52×52px, 버튼 간격 6px로 표시한다. 한 번 탭하면 한 번 이동하며 길게 눌러도 자동 반복하지 않는다. `touch-action: manipulation`으로 방향패드의 더블 탭 확대를 막고 보드 스와이프는 함께 지원한다.

방향패드 옆의 X 공격·하드 공격 버튼은 현재 보유량을 `0 / 3`으로 표시한다. 공격권이 없거나 대전 연결·일시정지·설정창 등으로 조작이 잠겨 있으면 비활성화하며, 기존 공격 처리 함수를 사용한다. 보드 옆 3칸 표시와 공격 단축키도 유지한다. 모바일 대전 최소 높이는 660px로 두고 그보다 작은 화면에서는 스크롤을 허용한다.

## 닉네임과 계정 삭제

닉네임은 앞뒤 공백을 제거한 1–32자이다. `players.name`이 기준이며 헤더·다음 대전·순위에 반영한다. 완료 경기의 닉네임은 당시 기록으로 남는다.

계정 삭제는 현재 이메일을 직접 입력하고 최종 버튼을 눌러야 실행한다. 기존 대전 서버의 `POST /account/delete`가 Bearer 토큰을 검증하고 본인 계정만 삭제한다. 관리자 계정은 먼저 별도로 권한을 해제해야 한다. 열린 경기 또는 저장 대기 결과가 있으면 삭제를 거절하고, 처리 중에는 새 매칭을 막는다. 세션을 전역 해제한 뒤 Supabase Admin API로 계정을 삭제한다. 비밀 키는 소켓 서버에만 둔다.

삭제 범위: 로그인 계정, 프로필, 코인 지갑, 계정 설정, 랭크·개인 통계. 상대방의 경기 기록은 유지하되 삭제된 참가자의 이름을 `Deleted player`로 익명화하고 계정 참조를 제거한다. 운영 감사 기록은 유지한다. 브라우저의 별도 게스트 설정은 계정 데이터가 아니므로 남는다.

현재 게임 서버가 단일 인스턴스로 매칭·진행 상태를 소유하는 구조에 맞춘다. 여러 소켓 인스턴스로 확장할 때는 활성 경기와 삭제 잠금을 공유 저장소에서 조정해야 한다.
