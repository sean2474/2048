# 친구, 메시지, 관전

- `/friends`: 닉네임 검색, 친구 요청·수락·거절·취소·삭제, 친구 간 1:1 메시지.
- 친구 메뉴는 헤더 탐색 링크 대신 로그인한 사용자의 프로필 아이콘 드롭다운에서 연다.
- 대시보드는 데모 보드를 유지하고 일일 퀘스트 아래 별도 친구 요약에 수락된 친구 최대 5명, 받은 요청 수, 친구별 읽지 않은 메시지 수를 표시한다. 메시지 버튼은 해당 대화(`/friends?chat=...`)를 바로 열고, 관전 버튼은 친구의 경기를 연다. 전체 목록은 친구 페이지에서 확인한다.
- 친구 목록과 대시보드에 온라인·오프라인·게임 중·싱글플레이 중을 표시한다. 관전 버튼은 서버가 진행 중인 멀티플레이 경기를 확인했을 때만 활성화한다. 상태 조회 실패/연결 끊김 시 관전을 비활성화하고 상태 확인 불가를 표시한다.
- 모든 로그인 페이지의 수동 입력을 받지 않는 별도 소켓이 접속 상태를 유지한다. 친구 목록은 본인 JWT로 확인하며, 서버의 실제 접속·게임 상태를 5초마다 갱신한다. 여러 탭 중 하나가 열려 있으면 온라인이다. 토큰 갱신 시 상태 연결도 다시 인증한다.
- 상태는 같은 게임 서버에 접속한 친구 기준이다. 개발 서버와 운영 서버의 접속 상태는 서로 공유하지 않는다.
- 온라인 친구에게 대전을 신청하면 상대의 현재 페이지에 수락·거절 팝업이 표시된다. 수락하면 방 코드 없이 두 탭을 같은 친구 대전으로 이동시킨다. 신청 취소·거절·접속 종료·30초 만료를 양쪽에 알린다. 계정당 하나의 신청만 유지하며 발신은 5초 간격으로 제한한다.
- 수락 시 서버가 친구 관계·정지 여부·실제 접속·게임/매칭 상태를 다시 검사한다. 여러 탭의 동시 수락은 경기 하나만 생성하고, 신청한 탭과 수락한 탭만 이동한다. 친구 대전에는 랭크 점수가 적용되지 않는다.
- 닉네임 자동완성은 기존 Supabase `social_players` RPC의 대소문자 구분 없는 부분 검색을 사용한다. 1~32자를 300ms 지연 조회해 최대 8명을 추천하며, 한글 조합 중 조회와 이전 검색 응답은 취소한다. 방향키·Enter로 선택하고 Escape로 닫는다. 검색 버튼으로 전체 검색 결과(최대 20명)도 볼 수 있다.
- 현재 대전 랭킹 TOP 50의 메뉴에서 친구 추가와 관전으로 이동한다.
- `/watch/[playerId]`: 친구의 진행 중 멀티플레이 경기 또는 현재 TOP 50 플레이어의 랭크전을 관전한다. 로그인 필요. 싱글플레이 관전은 포함하지 않는다.
- 관전은 별도 소켓 역할이며 플레이어 세션을 끊거나 게임 참가 슬롯을 차지하지 않는다. 이동·능력·항복·매칭 핸들러를 등록하지 않는다.
- 서버가 관전 권한을 확인하고 5초마다 재검사한다. 실패하면 구독을 해제한다. 경기 중단·재접속·최종 결과를 전달한다.

## 저장과 접근 권한

`social` 및 `social_single_character_names` 마이그레이션이 친구 관계와 메시지를 저장한다. 회원 자신의 관계와 대화만 읽을 수 있도록 RLS를 적용하며, 쓰기는 검증된 RPC만 허용한다. 검색은 공개 닉네임·프로필 아이콘만 반환한다.

친구 목록은 최대 100명(대기 요청 포함), 발신 대기 요청은 최대 20개다. 메시지는 수락된 친구에게만 전송할 수 있고, 최대 1,000자·분당 30개다. 재시도 키로 중복 저장을 방지한다. 최근 50개부터 불러오며 이전 메시지를 추가로 조회할 수 있다. 친구 삭제는 관계를 해제하며 기존 대화는 보존한다. 계정 삭제 시 해당 계정의 메시지와 친구 관계도 제거된다.

Supabase Realtime으로 관계·메시지 변경을 갱신한다. 연결이 끊기면 30초 주기 조회로 복구한다. 관전 권한 조회에는 기존 소켓 서버의 Supabase 서비스 자격 증명이 필요하다.

로컬에서도 웹과 소켓 서버가 같은 Supabase 프로젝트를 사용해야 한다. 로컬 대상은 `2048-staging`이다. 기존 운영 DB에만 있던 `social`, `social_single_character_names` 마이그레이션을 스테이징에도 적용한 이력이 있으며, 이후 환경별 통합·배포 상태는 [통합 기록](full-performance/integration.md)을 따른다. `PGRST202`는 localhost 제한이 아니라 연결된 DB에 RPC가 없다는 오류다. 새 번역이 적용되지 않은 열린 탭은 전체 새로고침한다.

## 검증

- `pnpm test`: DB 접근 권한, 친구 수락 조건, 메시지 중복·길이·빈도·페이지 조회, 관전 권한·통제 불가·재접속·종료·권한 회수와 기존 게임 회귀 검사.
- `pnpm typecheck`, `pnpm lint`.
- `pnpm --filter socket exec tsx --test tests/friend-challenges.test.ts`: 동시 수락·권한·친구 관계 재검증·게임 중 차단·거절/취소/만료/접속 종료 검사.
- `pnpm --filter socket exec tsx --test ../web/tests/friend-challenges.browser.mjs`: 데스크톱 대시보드/친구 목록의 신청, 모바일의 다른 페이지에서 수락·거절, 두 브라우저의 같은 경기 입장과 실제 이동 확인.
- `pnpm --filter socket exec tsx --test ../web/tests/social.browser.mjs`: 로컬 가상 계정의 요청·수락·메시지 전송 실패/재시도/복원, 30초 복구 조회, 실제 로컬 소켓 관전, 모바일 가로 넘침 검사. 실제 사용자에게 메시지를 보내지 않는다.
- `node --test apps/web/tests/social-discovery.browser.mjs`: 자동완성 지연 조회·이전 응답 무시·한글 조합·키보드/마우스 선택·오류·모바일, 대시보드 친구/요청/읽지 않은 메시지·대화 이동·로딩/빈 목록/재시도·영문/비로그인 검사.
- 아래 `docs/social/` 파일은 기존 검증 스냅샷이다. 새 브라우저 실행의 캡처는 `test-results/social/`에 생성한다.
- 화면 기록: `docs/social/friends-desktop.png`, `friends-mobile.png`, `watch-mobile.png`.
- 자동완성/대시보드 화면: `docs/social/autocomplete-desktop.png`, `autocomplete-mobile.png`, `dashboard-desktop.png`, `dashboard-mobile.png`.
- 대전 신청/입장 화면: `docs/social/challenge-button-desktop.png`, `challenge-incoming-mobile.png`, `challenge-game-desktop.png`, `challenge-game-mobile.png`.
- 위 초기 UI 브라우저 파일은 `http://[::1]:3001`을 고정 사용하며 `SOCIAL_TEST_ORIGIN`을 읽지 않는다. 가상 계정과 임시 소켓 서버를 사용하는 수동 검사이므로 전용 worktree의 개발 서버와 포트가 맞는지 먼저 확인한다.
- 현재 서버 페이지의 친구 메시지·관전 재시도·게스트 차단 회귀는 `node --test apps/web/tests/page-islands.browser.mjs`로 검사한다. 이 검사는 자체 로컬 API fixture와 독립 포트·빌드 폴더를 사용한다.
