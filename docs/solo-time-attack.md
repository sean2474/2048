# 싱글플레이와 게임 메뉴

`/solo`는 4×4 보드를 사용하며 대전의 5×5 보드와 구분된다. 기존 game-core 이동/생성 로직과 BoardView, 키 설정, 스킨, 효과음을 재사용한다. 공격, 능력, 되돌리기는 없다.

타임어택은 시작 요청을 서버가 처리한 시점부터 2048 달성까지 측정하며 최대 1시간이다. 무한모드는 시간제한 없이 2048 이후에도 계속 진행하고, 2048·4096·8192 달성 즉시 보상을 저장한다. 게스트도 두 모드를 플레이할 수 있지만 랭킹·영구 보상은 로그인 계정만 저장한다.

| 모드 | 조건 | 스킨 | 등급 |
|---|---|---|---|
| 타임어택 | 2048 완주 | 구리빛 질주 | 레어 |
| 타임어택 | 10분 이내 | 은빛 물결 | 레어 |
| 타임어택 | 6분 이내 | 황금 섬광 | 에픽 |
| 타임어택 | 4분 이내 | 폭풍 여우 | 레전더리 |
| 타임어택 | 2분 이내 | 시간의 용 | 레전더리 |
| 무한모드 | 2048 | 비취의 길 | 레어 |
| 무한모드 | 4096 | 황혼의 궤도 | 에픽 |
| 무한모드 | 8192 | 별빛 불사조 | 레전더리 |

타임어택 랭킹은 `/leaderboard?mode=solo`에서 본다. 계정별 최고 기록 상위 50명을 시간 → 유효 이동 횟수 → 달성 시각 → 계정 ID 순으로 정렬한다. 로그인한 사용자는 50위 밖이어도 자기 순위를 확인한다. 랭크전도 현재/지난 시즌의 내 순위를 표시하고 시즌 선택은 커스텀 메뉴를 사용한다. 이전 5×5 테스트 기록은 새 4×4 랭킹에 포함하지 않는다.

대전 찾기는 일반전·랭크전·친선전 세 버튼으로 구성한다. 친선전은 방 만들기/참여 모달을 열고, 비로그인 랭크전 클릭은 로그인 안내 모달을 연다. 매칭 소개에는 즉시 입장 버튼이 없고 자동으로 게임 화면으로 이동한다. 세 모드 아이콘은 공통 GameEmblem의 40px 선화로 통일한다.

어느 페이지에서든 로그인 계정은 자동 출석한다. 재접속·중복 요청은 같은 날 중복 처리하지 않는다. 대시보드에는 연속 출석일을 표시하고, 업적은 미해금 항목 다음에 해금 항목을 배치한다. 헤더의 대시보드 링크를 제거하고 로고로 홈에 이동한다. 코인은 공통 노란색 아이콘을 사용한다.

## 서버와 저장

클라이언트는 모드 선택/시작/상태 조회/방향 입력/저장 재시도만 전송한다. 서버가 보드, 점수, 승리, 시간을 계산한다. run ID와 순번으로 중복 입력을 방지한다. 싱글·대전 모두 이동 요청을 최근 1초당 최대 20회로 제한하고 초과 입력만 무시한다. 정상적인 빠른 입력과 70ms 키 반복을 허용하며, 제한 이하의 봇까지 탐지하는 기능은 아니다.

`record_solo`와 `record_solo_endless`는 최고 기록과 업적 지급을 같은 트랜잭션에서 처리한다. 서비스 역할만 기록할 수 있으며 일반 계정은 자기 원본 기록만 읽는다. 공개 랭킹은 정지 계정을 제외한다. 해금·장착 검증 및 계정 삭제 시 기록 삭제도 적용한다.

진행 중 보드와 저장 실패 기록은 메모리에 보관한다. 같은 탭 재접속 시 복원되며 시간은 멈추지 않는다. 70분 동안 요청이 없으면 정리한다. 저장 실패는 재시도할 수 있고 저장되지 않은 기록이 있으면 새 게임 시작을 막는다. 서버 재시작 복구는 지원하지 않으며 필요할 때 영구 outbox를 추가한다.

## 2026-10-17 검증과 적용

- 전체 자동 테스트 184개, 타입 검사, 린트, 웹 프로덕션 빌드 통과.
- 4×4/기존 5×5 이동, 두 모드의 종료·지속 조건, 8개 보상 경계, 재접속, 저장 재시도·중복 방지, 20회 이동 제한, DB 권한, 50위 밖 내 순위를 자동 검사했다.
- `apps/socket/tests/solo-remote-smoke.ts`는 staging 임시 계정으로 실제 소켓 이동과 서버에서 준비한 달성 보드를 이용해 8개 보상·장착·내 순위·중복 출석을 검사했다. 완주 보드는 테스트용으로 준비한 것이며 사람이 전체 판을 플레이한 검증은 아니다. 계정은 검사 후 삭제했다.
- 브라우저에서 친선전/로그인 안내 모달, 두 싱글 모드의 4×4 보드와 이동, 자동 출석, 업적 정렬, 커스텀 시즌 메뉴, 싱글 내 순위를 확인했다. 영문 헤더는 1024px에서 한 줄, 375px에서는 가로 넘침이 없었다.
- 실제 터치 기기의 스와이프와 운영 서버 배포는 검사하지 않았다.

현재 로컬과 staging 대상은 `nwdjucplpyorwiwshxtf`다. `20261017080304_solo_time_attack.sql`과 `20261017083751_solo_modes_4x4.sql`을 적용했다. 운영 앱/소켓 배포는 하지 않았다.

### 이전 세션의 운영 원복 이력

작업 중 이전 세션의 연결 정보를 잘못 사용해 운영 `rbfujqjvkfdgaofztrdq`에 `20261017080106_solo_time_attack`을 적용했다가, 데이터/장착 항목이 없음을 확인하는 트랜잭션으로 `20261017080215_revert_unreleased_solo_time_attack`을 적용해 원복했다. 기존 업적 함수·장착 검증·제약을 복원했고 신규 테이블/RPC가 없음을 확인했다. 원격 이력의 두 작업은 삭제하거나 수정하지 않았다. 다음 운영 배포 때 이 원복 이력을 고려하고 staging 기능 마이그레이션을 적용한다. 운영의 추가 이력을 무시한 일괄 `db push`는 사용하지 않는다.

## Git 통합 검증

기능 브랜치 `codex/solo-modes-and-navigation`은 공유 작업 폴더를 보존하고 별도 worktree에서 이 작업의 변경만 복원했다. `origin/staging`의 티어 컬렉션 변경을 병합하며 카탈로그·업적 화면·캐릭터 타일·번역·효과·테스트의 겹친 부분을 합쳤다. 통합 후 자동 테스트 200개, 전체 타입 검사·린트, 웹 프로덕션 빌드를 통과했다. favicon은 흑백 원형의 2×2 타일 심벌이며 ICO의 16·32·48·64·128·256px 엔트리를 확인했다.

다른 작업에서 진행하는 친구 기능·일일 퀘스트·싱글 진행 상황의 DB 저장은 이 기능 브랜치에 포함하지 않았다. 운영 배포와 통합 후 브라우저 전체 회귀 검사는 수행하지 않았다. staging 웹 반영 전에는 이 브랜치의 소켓 서버도 함께 준비해야 한다.
