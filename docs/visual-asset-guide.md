# 아이콘 · 이미지 · 스킨 제작 가이드

최종 갱신: 2026-10-17

2048 Duo의 새 시각 요소를 만들거나 수정할 때 사용하는 기준이다. 기존 화면의 따뜻한 색상은 유지하고, 기능 아이콘은 간결한 선으로, 수집용 아트는 테마가 드러나는 그림으로 표현한다. 경쟁·티어 화면은 절제된 분위기, 캐릭터 스킨은 개성을 우선한다.

과거 작업 보고서와 이 문서가 다르면 아래 공통 컴포넌트와 최신 사용자 요청을 먼저 확인한다. 새 스타일을 추가할 때 이 문서와 실제 렌더링을 함께 갱신한다.

## 1. 먼저 고를 것: 기능 아이콘인가, 수집용 그림인가

| 용도 | 제작 기준 | 기준 소스 |
| --- | --- | --- |
| 로고·코인·꾸미기·책·설정·프로필 등 UI 심볼 | 단색 선, 같은 굵기·끝 처리 | [GameEmblem](../apps/web/src/components/widget/game-emblem.tsx) |
| 닫기·뒤로·체크·볼륨 같은 일반 조작 | 설치된 Lucide 아이콘 재사용 | 기존 Button·Dialog·AudioControls |
| 랭크 티어 | 기존 금속색·문장 형태의 위계 유지 | [TierIcon](../apps/web/src/components/widget/tier-badge.tsx) |
| 플레이어 프로필 그림 | 원형 크롭 안에 캐릭터와 고유 배경 | [ProfileIcon](../apps/web/src/components/widget/profile-icon.tsx), [원본 SVG](../apps/web/public/profile-icons) |
| 능력 그림 | 효과를 한눈에 설명하는 주 피사체 하나 | [AbilityIcon](../apps/web/src/components/widget/ability-icon.tsx), [원본 SVG](../apps/web/public/ability-icons) |
| 보드·타일 | 공통 타일 렌더러와 스킨 토큰 | [카탈로그 토큰](../packages/schema/catalog.ts), [NumberTile](../apps/web/src/components/2048/number-tile.tsx) |
| 레전더리 합성 장식 | 숫자 주변의 짧은 테마 연출 | [MergeFlair](../apps/web/src/components/2048/merge-flair.tsx), [애니메이션 CSS](../apps/web/src/styles/animations.css) |

UI 심볼에 팔각 금속 배지·입체 테두리·그라데이션을 다시 씌우지 않는다. 이 규칙은 티어 문장이나 프로필 일러스트의 색상 표현까지 없애라는 뜻이 아니다. 프로필과 능력은 동물 외에도 기사·기계·마법·도구·기하 테마를 사용할 수 있다.

## 2. UI 선 아이콘

- `viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `strokeWidth={1.65}`가 기본이다.
- `strokeLinecap="round"`, `strokeLinejoin="round"`를 사용한다. 바깥 여백은 보통 2–3단위로 두고, 별 끝 등 광학 보정만 1.5단위까지 허용한다.
- 하나의 실루엣과 핵심 디테일만 남긴다. 작은 붓털·리벳·반사광·여러 겹 테두리와 교차점의 선 중첩을 피한다.
- 16·24·32px에서 확인한다. 16px에서 알아보기 어렵다면 확대하는 대신 내부 선을 덜어낸다.
- 새 심볼은 `GameEmblem`의 종류로 추가해 모든 위치에서 재사용한다. 같은 뜻의 SVG를 페이지별로 복사하지 않는다.
- 페이지 제목은 `PageHeading`의 공통 여백을 사용한다. 그림 크기와 클릭 영역은 별개이며, 아이콘 버튼의 터치 영역은 최소 44×44px이다.
- 옆에 텍스트가 있으면 `aria-hidden="true"`, `focusable="false"`. 아이콘만 있는 버튼에는 번역된 `aria-label`을 붙인다.

기본 SVG 형태:

```tsx
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
  strokeWidth={1.65} strokeLinecap="round" strokeLinejoin="round"
  aria-hidden="true" focusable="false">
  {/* 주 실루엣과 최소한의 디테일 */}
</svg>
```

## 3. 색상과 형태

UI 색상은 [globals.css](../apps/web/src/app/globals.css)의 토큰을 사용한다. 자산 하나 때문에 페이지 전체 색상을 바꾸지 않는다.

| 역할 | 현재 기준 |
| --- | --- |
| 화면 배경 | `--background` · `#f6f3eb` |
| 카드 | `--card` · `#ffffff` |
| 기본 글자·선 | `--foreground` · `#282b28` |
| 주요 동작 | `--primary` · `#a4432d` |
| 보조 표면 / 글자 | `--secondary` · `#e9ede4` / `--secondary-foreground` · `#43523b` |
| 비활성 설명 | `--muted-foreground` · `#686b61` |
| 테두리 | `--border` · `#e2ded3` |

카드 모서리와 아이콘 자체를 별도로 장식하지 않는다. 보드 바깥 radius는 `타일 radius + 보드 padding`을 따른다. X 블록의 빨간색·✖, 하드 블록의 짙은 회색과 테두리는 어떤 스킨에서도 유지한다.

## 4. 이미지·캐릭터 제작과 내보내기

1. 먼저 용도, 최종 표시 크기, 테마, 반드시 보여야 할 형태를 한 문장으로 정한다. 가장 가까운 기존 자산 하나를 기준으로 함께 비교한다.
2. 간단한 심볼·캐릭터는 편집 가능한 SVG를 우선한다. 복잡한 일러스트에 이미지 생성 도구를 쓰면 최종 그림과 생성 프롬프트·기준 자산·후처리 내용을 작업 문서에 남긴다.
3. 캐릭터는 얼굴이나 상징 하나를 중심에 둔다. 프로필은 현재 160×160 SVG 좌표계이며 실제 표시 크기 24·40·80px와 원형 크롭을 모두 확인한다. 눈·귀·중요 상징이 크롭 밖으로 잘리지 않게 한다.
4. 능력 그림은 실제 효과를 설명해야 한다. 미확정 기능의 아이콘을 완성된 전투 효과처럼 표현하지 않는다. 현재 화면에서 사용하는 능력 ID·기획을 먼저 확인한다.
5. 래스터가 필요한 경우 WebP 또는 PNG를 사용하고 최종 표시 크기의 2배를 기본으로 내보낸다. 잘라 쓸 자산은 실제 투명 배경으로 내보내며, 흰 배경이나 체크무늬를 그림 안에 굽지 않는다.
6. 글자·번역·숫자·코인 잔액을 이미지에 넣지 않는다. 실제 텍스트로 렌더링한다. 외부 폰트·스크립트·외부 이미지 참조 없이 자산 자체로 표시돼야 한다.
7. 이름은 의미 있는 소문자 kebab-case를 사용한다. 프로필·능력은 기존 ID와 파일명을 일치시킨다. 앱 기본 SVG는 위 표의 경로에 두고, 관리자 추가 이미지는 [콘텐츠 카탈로그](content-catalog.md)의 Storage 업로드로 연결한다. 관리자 업로드는 PNG/JPEG/WebP만 받으며 SVG는 신뢰된 저장소 자산의 초기 seed에만 사용한다.

## 5. 스킨 등급과 숫자 가독성

| 등급 | 시각적 차이 |
| --- | --- |
| 일반 | 보드 색과 재질 톤 중심 |
| 희귀 | 타일 패턴 추가 |
| 에픽 | 보드 배경과 타일 테마를 함께 변경 |
| 레전더리 | 캐릭터·상징 타일 + 스킨별 합성 모션·효과음 |

숫자는 항상 가장 먼저 읽혀야 한다. 캐릭터 얼굴과 숫자 영역을 분리하고, 장식은 숫자 판 안으로 들어오지 않게 한다. `NumberTile`을 카탈로그와 실전에 함께 사용한다. 작은 상대 보드와 2·128·1024·2048·32768까지 확인한다. 장착한 스킨은 해당 플레이어 보드에만 적용하며 게임 판정과 점수는 바꾸지 않는다.

### 업적 전용 수집품

보상의 획득 경로는 [DB 업적 카탈로그](content-catalog.md)에서 연결한다. 정적 schema 목록은 초기 정의와 호환 용도이며 현재 공개 목록을 대신하지 않는다. 등급은 시각 표현을 설명하며 해금 조건과 별개다. 잠금 상태에서도 원래 그림과 조건을 미리 볼 수 있게 하고, 잠금·해금·장착 여부를 색상만으로 구별하지 않는다.

| 보상 | 표현 기준 | 획득 경로 |
| --- | --- | --- |
| 새벽의 서약 · 희귀 보드 | 숫자 영역을 비운 일출 테두리 패턴 | 7일 연속 출석 |
| 출근왕 · 프로필 | 왕관·서류 가방·시계의 큰 실루엣, 원형 크롭 | 30일 연속 출석 |
| 승리의 선봉 · 프로필 | 투구와 월계수, 기존 동물 프로필과 구별되는 테마 | 유효 대전 10승 |
| 룬의 성소 · 에픽 보드 | 비취 석조 배경과 숫자 바깥의 각인 마법진 | 유효 대전에서 1024 달성 |

저장소 기본 프로필은 160×160 SVG를 사용하고 관리자 이미지도 같은 원형 크롭의 `ProfileIcon`으로 표시한다. 보드는 스킨 토큰·공통 미리보기·실전 타일을 함께 사용한다. 전용 보드를 추가할 때 코인 상품으로 자동 등록하지 않는다. 규칙과 소유권은 [업적·상점 문서](achievements-and-shop.md), 이번 자산 캡처는 [업적 보상 자료](achievement-rewards)에 둔다.

## 6. 레전더리 합성 모션

현재 렌더러는 `cat`, `bunny`, `sentinel`, `runeknight`, `arcanist`, `diamond`, `crown`, `fox`, `dragon`, `phoenix` 캐릭터를 지원한다. 공개 스킨은 관리자가 선택한 토큰을 사용한다. 아래는 초기 다섯 테마의 기준 예시다. 새 스킨을 추가할 때 기존 동작을 사용할 수 있지만 새로운 모션 종류는 코드 구현이 필요하다.

| 스킨 | 타일 동작 | 주변 장식 |
| --- | --- | --- |
| 냥냥 클럽 | 눌렸다가 말랑하게 반동 | 위로 사라지는 발자국 |
| 토끼 정원 | 짧게 뛰고 착지 | 흩어지는 꽃잎 |
| 아이언 센티널 | 압축·고정되는 기계 반동 | 닫히는 코너 프레임 |
| 룬 나이트 | 짧게 내려찍고 복원 | 펼쳐지는 다이아몬드 룬 |
| 아케인 오더 | 살짝 떠오르며 회전 | 회전하는 이중 마법진과 별 |

- 합성 연출은 현재 **420ms, 1회**다. 이동은 기존 보드 로직에 맡기고 결과 타일에만 장식을 붙인다.
- 숫자를 회전시켜 읽기 어렵게 하거나, 화면 전체를 흔들거나, 연속 점멸시키지 않는다. SVG 중앙은 비우고 장식은 테두리 주변에 둔다.
- `transform`과 `opacity`로 움직인다. 주변 장식의 기본 프레임은 타일의 140%이며, 작은 보드에서도 이웃 숫자와 보드 밖 조작 버튼을 가리지 않는지 확인한다.
- 효과는 입력을 기다리게 하지 않는다. 새 이동이 오면 게임 상태를 우선하며 이전 효과를 끝까지 보여주려고 보드를 멈추지 않는다.
- 실전 `Tile`과 `SkinMergePreview`에서 같은 `MergeFlair`·CSS를 사용한다. 새 효과의 시간 변경 시 미리보기 완료 타이머도 함께 맞춘다.
- `prefers-reduced-motion: reduce`에서는 타일 동작과 장식을 끈다. 합성된 숫자는 정상 표시한다.
- 소리는 [GameAudio](../apps/web/src/lib/game-audio.ts)와 `useAudio`를 재사용한다. 음소거·볼륨을 따르고 미리보기는 명시적으로 재생할 때만 소리를 낸다. 상대 합성 소리를 중복 재생하지 않는다.

## 7. 제작 요청 템플릿

**UI 아이콘**

> 2048 Duo의 [기능] 아이콘. 24×24 SVG, 1.65 두께의 단색 선, 둥근 끝과 접합부, currentColor. [주 형태] 하나와 최소 디테일. 기존 GameEmblem과 같은 시각적 무게. 16px에서도 식별 가능. 텍스트·금속 배지·그라데이션·입체 그림자 없음.

**프로필·테마 이미지**

> 2048 Duo의 [용도] 그림. 테마는 [주제], 주 피사체는 [대상], 참고 자산은 [경로]. [최종 크기]에서 읽히는 큰 실루엣과 제한된 내부 디테일. 따뜻한 바탕과 선명한 윤곽, 포인트색 [색상]. [원형 크롭/투명 배경/정사각형]에 맞춤. 글자·숫자·워터마크 없음. 캐릭터 타일이면 하단 숫자 영역을 비워 둘 것.

## 8. 완료 전 확인

- 기존 자산 옆에서 선 굵기·밀도·크기·톤이 맞는가?
- 공통 컴포넌트를 사용하고, 같은 자산의 다른 화면도 함께 갱신됐는가?
- 375×812, 768×1024, 1440×900에서 확인했는가?
- 숫자와 버튼 문구가 잘 보이고, 키보드 포커스·터치 영역·대체 이름이 유지되는가?
- 잠금·미선택·선택 상태를 이미지 색상만으로 구분하지 않는가?
- 합성 시작·중간·종료, 반복 재생, 창 닫기, 음소거, 동작 줄이기를 확인했는가?
- SVG 원본과 실제 렌더링 캡처를 남기고 타입 검사·관련 테스트를 통과했는가?
